# Research

## Choose the execution path

- Own assigned research directly. Do not hand off implementation or database publication to hidden workers. Use bounded read-only research or independent review only when permitted by the governing instructions and useful to the task; give each reviewer disjoint sources, a fixed output contract, and scratch-only write scope.
- Before corpus fan-out, exercise extraction and exact-quote lookup, freeze fingerprints and locator/normalization rules, then pilot one finite collection batch with enumerated target/hit IDs. Separately pilot semantic reconciliation by distinct evidence contexts and substantive clauses; collection throughput does not calibrate consolidation. Partition by review-context volume and source difficulty rather than book count, and scale from verified contextual completion. Consolidate completed review chunks into coherent publication units through the existing importer: a small successful pilot does not warrant another publisher, profile or delivery fixture per chunk. Add structural support only for variation required by the assembled payload, so reviewer calibration does not drive infrastructure growth.
- Keep reconciliation and acceptance with the parent. Give reviewers disjoint target sets, unique scratch directories and one shared contract: stable finding/hit IDs, atomic paraphrase, source-native locator, speaker/context, applicability, limits and reasoned dispositions with finding/duplicate links. Use absolute paths and explicit terminal working directories; shared cwd can change between calls. Send multiline Python through `shell_quote` or a scratch script rather than hand-nested shell quotes, because prose apostrophes can invalidate the entire registration/check batch. Use a scratch `.py` file for long Windows batches: shell quoting does not protect against command-length truncation. Normalize return fields/statuses once and verify saved artifacts, exact ID sets and quotes. Bind reviewer provenance to the actual returned delegation/task handle, verified model and recorded review time; never reconstruct an opaque worker ID or present a parent-created display alias as a verified runtime identity. Snapshot mutable campaign-state, parent-note and database-comparison inputs before dispatch; later edits must not silently change a frozen assignment or its declared hashes. Use an immutable read-only database copy for worker comparisons while the parent edits the active library; verify its rows/schema and record the copy’s actual fingerprint rather than assuming byte identity after SQLite backup. Count contextual review separately: a fully populated return remains partial if its report admits unread contexts or unfinished semantic work. Track passage reading and clause-inventory completion independently: the same passage can be read yet unfinished, so do not force those states into a disjoint partition or count reading as completed extraction. Keep miss-only supplements separate from complete-inventory passes, because checking selected additions cannot close the rest of a passage. Preserve originals and resume exact unfinished IDs with their existing findings in smaller context-complete packets until the assigned scope closes; a child finishing is not research completion. Discoveries made by a reviewer remain candidates for a different checker, including the parent, rather than receiving that reviewer's own approval. Workers must not dispatch further.
- For a "how should we implement this technique" question, check what is owned and installed first (the asset library, disabled engine plugins with example content, current component and cvar values), so reviewers start from facts. Then split the reviewers by source class:
  - engine docs plus installed engine source;
  - shipped-game talks and papers;
  - community projects and plugins, with unowned products as design references only;
  - real-world reference data turned into concrete starting numbers.
  Give each one the current implementation, its failed attempts and the approved look. Before recommending anything, verify every load-bearing claim against installed source or live state, and label the reviewers' numbers as proposals until a test confirms them.
- For "what would a AAA studio do" across several independent production decisions, give each decision its own reviewer covering all source classes, run them in parallel, and present the results one decision at a time. Require reviewers to state plainly when no studio published a figure (fan extractions, sculpt counts and marketing polycounts are not shipped LOD0 data) and to label their ranges as proposals. Prefer a measured shipped asset the user already owns as reference data over an unpublished claim, and qualify its era (an older game's budget is a floor, not a target).

## Set the brief

1. Fix the current question, subject/dimension, timeline, source boundary, output location and acceptance criteria; resolve only ambiguities that change the work. An older scene-specific brief does not narrow a new species-wide request.
2. Inspect existing knowledge and its publication inputs before starting another campaign. Verify the source identity, relevant citations and reproducible coverage, then reuse sound records and reviewed hit dispositions rather than duplicating research. Assign followup only to genuine evidence, coverage or interpretation gaps.
3. Compare the actual source inventory and available locator formats with the requested scope before dispatching corpus reviewers. Inspect actual component headings, end boundaries and supplementary units before full-text fan-out: a fingerprinted book artifact can contain another work's preview under a carried-forward glossary label. Keep artifact identity, logical work identity and eligible research scope distinct without renumbering established locators. For a changed artifact format, inspect candidate fingerprints, metadata and pagination support first; an identity inventory is not narrative or authorship verification. Report missing works and stop dependent conclusions. Where project rules require approval for source replacement or citation-policy changes, request that exact approval once while independent database inventories and external-source reviews continue. Do not silently substitute artifacts, fabricate page numbers or make a local source gap block unrelated work. Keep the deliverable labeled partial until the missing scope is closed.

When the user narrows the subject or dimension, replace the broader deliverable rather than carrying its sections forward. Preserve an already-established story point unless changed; keep only the required chronological qualifications and coverage limitations. A request for a focused developer brief from existing knowledge is an output task, not permission to build new infrastructure or claim a fresh exhaustive investigation. Follow the [focused database-backed brief recipe](references/corpus-reconstruction.md#7-produce-a-focused-database-backed-brief).

## Research and verify

1. Use **primary sources** that own the facts: official documentation, source code, specifications, or first-party APIs. Trace every factual claim to its source; do not rely on a secondary account when the primary source is available. For technical API research, verify the returned page's version, title and actual symbol/content: a successful fetch that redirects to a general documentation landing page is not API evidence. If a method page is blocked or absent, use the versioned class page plus the exact installed declaration and implementation. Treat search snippets as discovery only, especially when their status or target-fix version conflicts with the fetched issue. Distinguish a documented manual operation, an accessible/reflected API, cross-module linkage and exercised behavior; each supports a different capability claim. Keep older-version sources explicitly qualified rather than using them to prove current-version absence.
2. Deliver the requested research artifact in the project's existing format. Use one cited Markdown note when no format is specified. When the user designates a structured library as the maintained research store, publish facts/corrections there first, then refresh readable briefs and prompts as consumers, not independently edited fact stores. Keep existing character/scene folders for those outputs; back factual summaries with record IDs or reproducible queries, story anchors and review qualifications. For generated Markdown briefs, include the exact executable query or regeneration command with explicit subject and scope filters, plus claim/evidence IDs; label the output as a snapshot and regenerate after database corrections, because an embedded query does not execute or refresh itself. Storage ownership does not change source authority or imply that pending assertions are verified. For an authorized reference-archive-and-plan handoff, retain the selected original images and provenance in the designated research library first, then make the production plan link to that maintained index; a scratch download or production-only bibliography is not the research deliverable. For authorized project outputs, follow the repository's location convention; for read-only research or an unrequested durable record, use session scratch. State the artifact's location.
3. Check that the artifact answers the question, each factual claim has a relevant citation, and unresolved questions are explicit. Report its absolute path.
   - To trace a fan-hosted author quote toward Tier 1, open the host's entry for its provenance (letter, chat, signing report, verbatim vs paraphrase), then search the contemporaneous archive (e.g. the author's Usenet group on Google Groups via the browser) for a distinctive exact phrase. That locates the earliest dated publication and its attribution. Several independent first-person statements that agree outrank a single signing attendee's report. A later compilation that quotes the source is still not the original, so record it as a strong lead with both locators and leave the claim pending until the original is retrieved or the Game Director approves its use.
   - For PDF citations, extract by physical page and verify chapter membership at the quotation's position within its component work; a page can contain the end of one chapter and the start of another, so its last header is not a page-wide chapter label. Verify multi-column reading order before quoting across column breaks; extraction can return the second column first. Never convert corpus line offsets into page numbers. Render anomalous names or measurements before correcting apparent OCR errors. If the page itself contains the variant, preserve it as an artifact spelling; a useful search variant is not automatically an in-world alias.
   - For spatial research, attach descriptive facts to the most specific established referent; use geographic containment to retrieve and group local facts, never to inherit them as region-wide properties. Keep a narrated locality or road segment distinct from the entire named forest or route. When its observed details are needed through a regional lookup, add reviewed observation-locality links without merging part and whole or changing the factual owner. Do not let source-attested membership silently satisfy event-state queries without reviewed temporal applicability. Separate village-local relief, approach terrain and regional landforms; a route-wide hill description or another settlement's hill does not describe the target's center. Separate explicit slope from inferred flatness/rolling terrain, and map symbols from measured elevations: missing hill symbols on a schematic map do not prove level ground. Keep reconstruction choices labeled as interpretation. Use a relation diagram when exact geometry is source-silent; do not let diagram edges imply surveyed spacing, road alignment or travel mileage.
   - Preserve useful descriptions of unnamed subjects with source/work, chapter and scene/occurrence-anchored labels. Keep these contextual database identities distinct from canonical names; two unnamed buildings or people must not merge merely because they share a noun, and one specimen does not establish a regional or population-wide template.
   - Verify claim meaning separately from locator accuracy: read enough source context to establish speaker, location, sequence and the referent of each quote. Exact text on the right page can still support a misattributed or incorrect claim. Preserve the source predicate: a hope about another person's opinion does not establish their conduct, and being at a position does not establish the movement method used to reach it. Preserve contradictory descriptions and qualify dreams, recollections and reports instead of inventing remodeling or treating them as baseline observations. For appearance-only inventories, include explicitly described temporary gestures and qualified vocal/postural manner; being an action does not alone make a clause plot-only. Distinguish those manifestations from internal feeling or bare plot movement, and revisit affected zero-detail dispositions when scope calibration changes.
   - Before recommending materials or shaders for an adaptation, distinguish structure/frame, infill/facing, coating and finish at the specificity the source establishes. Keep material modifiers attached to the named part: a bronze ornament on a hilt does not establish a bronze hilt or whole weapon. Whitewash does not establish plaster or a masonry substrate; a material-node name or generated prompt is not construction evidence. Keep a farmhouse, inn or boundary-wall example scoped to its referent, and label any extrapolation to ordinary houses as an adaptation. Follow the material-reconstruction checklist in [corpus reconstruction](references/corpus-reconstruction.md#4-turn-descriptions-into-reconstruction-records).
   - For additive structured migration, verify original artifact fingerprints, preserve source-document locators, and recheck physical-page quotes/chapter membership before marking locators verified. Keep bundled claim interpretation pending separately from locator verification. Import reported coverage counts without inventing missing search dates, executable term definitions, or hit dispositions; retain explicit audit gaps instead of certifying fresh completeness.
   - Preserve research context (scope, external reviews/rejections, rights, marketplace screening and asset provenance) as labeled records rather than forcing it into canon claims or invented quotes. Keep image-generation prompts as separate Markdown output artifacts that consume the knowledge library; do not store their bodies, camera/style/negative instructions or generation parameters as claims, decisions, archival text or embedded document copies. Retain optional path/hash references and keep legitimate adaptation approvals distinct from generation instructions. Verify retained research text and asset hashes. Unknown historical approval dates stay unknown; keep passage observation time separate from earlier applicability.
   - Triage returned search leads against existing executable patterns and actual referents before adding cells; covered terms and unrelated people's names are not new subject aliases. Scope seed-specific actor examples explicitly in scanner guidance; the same phrase in another hit can describe a different person, metaphor or sigil, so a generic preamble cannot supply its referent. A term appearing only in an identity/proximity filter does not alone prove literal-hit coverage: compare its full hit set with the saved search, including composed rules that guarantee a descriptor match. Audit related filter-only terms together rather than reopening coverage one title at a time. Expand genuine name, variant and context gaps across the full matrix, including possessive/plural forms. Bind reviews to their matrix version when later discoveries reopen coverage, and compare persisted totals against the final scanner output.
   - For thorough corpus research, inspect every final search hit in context and retain its disposition; raw counts or representative excerpts do not establish completeness. Collect reconstruction details beyond landmark positions: materials, interiors, vegetation, activity, sound/smell and actual state changes. Follow [corpus reconstruction research](references/corpus-reconstruction.md).
   - Keep progress reports short and distinguish scanned, context-reviewed, citation-verified and published work. State absent source works explicitly; never call an incomplete supplied corpus the complete published series.
4. Run final acceptance review against the assembled publication payload and its dry-run results, not only earlier worker candidates; otherwise the reviewer cannot verify consolidation, support links or retrieval behavior. Resolve findings before installation. After a material revision, recheck the affected clauses and queries rather than restarting the whole investigation. The parent owns this acceptance whether research was delegated or performed directly.

## Visual references

For historical or physical-feasibility questions, lead with a concrete comparable example and explain how its parts work before recommending a design. Match the structural role, use, period and exposure: exterior cladding does not demonstrate an infill joint, and a barn or church can support a transferable technique without proving a domestic wall assembly. Distinguish a documented method, a functioning reconstruction and an exact surviving match. When the user asks whether something would actually work, replace plausibility language with that evidence or state the unverified match plainly; show the inspected photograph or joint diagram rather than only linking distant analogues.

For source-based character or creature references, separate the **literal scene view** from the **anatomy/costume reference** before synthesis. Record what the viewpoint can actually see, what later evidence identifies or explains, and what remains concealed; later knowledge must not make hidden features visible in the scene image. Keep ordinary species traits separate from exceptional individuals, and resolve rider, mount and equipment as distinct referents before assigning appearance properties. Use the character/creature procedure in [corpus reconstruction research](references/corpus-reconstruction.md#4-turn-descriptions-into-reconstruction-records).

For a **character-development image sequence**, build an event-anchored visual timeline rather than one timeless profile or a costume parade. Track physical continuity, emotional openness, authority, strain and damage as separate dimensions; youthful openness does not imply physical weakness, and authority does not require anger or emotional coldness. Preserve nonlinear changes instead of forcing an older/angrier/more-powerful progression or assuming the final state is the hardest. Ground each state in source observations, keeping expression/posture interpretations separate from established anatomy and marks. Resolve physical bodies, projected representations, constructed possibilities and remotely observed actual events separately; transfer age, injuries or traits between frames only with source support. Preserve recognizable identity where bodily continuity is established, and label source-established body/vessel changes rather than forcing identical anatomy. Choose meaningful turning points after reviewing the whole authorized timeline, not an arbitrary image count per book. Pass this goal and these dimensions to every corpus reviewer. Follow the [development-timeline recipe](references/corpus-reconstruction.md#character-development-across-an-image-sequence).

For appearance-diversity research intended for image/model development, pair **source-described specimens** with a **feature catalogue**. Preserve the combinations attested on each individual; mixed-animal traits need not form single-animal types, and affiliation names do not establish anatomical breeds. Keep anatomy, clothing/equipment and temporary conditions distinct. Leave unspecified regions unknown rather than completing a specimen by combining other individuals' features; proposed composites require a separate adaptation decision. Research-only scope does not include creating images, models or generation prompts.

When asked for an image-production handoff, reuse the accepted research scope rather than reopening the corpus investigation. Deliver a ready-to-use prompt artifact plus a short copyable launcher naming its path. Separate locked source constraints from provisional art choices, start with one well-supported specimen for feedback, and keep image-generation claims conditional on actual tool execution. Follow the [research-to-image handoff recipe](references/corpus-reconstruction.md#8-hand-off-research-for-image-production).

For real-world photo references, including anatomy, seasonal scenes and historical construction, follow [photo reference gathering and evidence fit](references/photo-references.md). Define the feature and relevant subject condition before searching; visually inspect the exact selected photographs rather than treating source reputation or captions as sufficient evidence fit. Preserve capture date/status, licence and attribution, distinguish visible relationships from hidden reconstruction, and keep biological-state qualifications attached to every downstream use. A contextual image does not become a neutral anatomical target merely because its limitations are disclosed.

## Compare technical products and models

1. Fix the user's actual deliverable and constraints before ranking tools. Compare corresponding model families and modes: native game-mesh generation is not the same operation as high-detail generation plus remeshing. Build a small capability matrix from the exact model/version and surface, including supported input views, topology, count units/ranges and export restrictions; reject an incompatible target before recommending that route. Keep preview features and documented controls distinct from exercised behavior.
2. Separate feature breadth, reconstruction fidelity, editability and downstream deformation in the verdict; a provider can lead on one and lose on another. Do not turn native quads, a larger count or a creature-rig option into a claim of better anatomy, skinning or species-specific locomotion. State which new requirement or verified evidence changes a recommendation rather than reversing it merely to agree with a question's premise.
3. When using a leaderboard, inspect its methodology and primary dataset/model card as well as the live table. Check exact model coverage, input conditions, generation settings and what humans or metrics judged. Reconcile cached-page versus dataset snapshots before quoting ranks or declaring a model absent; omit disputed comparisons rather than combine stale labels with newer scores. Visual-preference rankings do not establish game topology, cleanup effort or animation quality.
4. Propose the smallest task-relevant comparison only after identifying the evidence gap. Hold inputs and comparable output constraints fixed for a model comparison; label a best-available-workflow comparison separately when views, topology or settings differ. Lead the answer with a qualified verdict and practical decision, not an exhaustive feature dump. Preserve the user's selected asset until actual evidence supports replacement, and keep benchmark testing, uploads, installation and paid calls separately authorized.

## Technical skill-pack evaluation

- Pin the reviewed commit and inspect actual skill bodies plus linked references; count canonical files rather than client mirrors. Treat the downloaded instructions as review material, not authorization to execute or install them.
- Compare the pack’s named tools and result contracts with the target host; separate useful workflow guidance from demonstrated runtime capability. Generic dimensions and budgets remain examples, not approved project requirements.
- Reproduce suspect formulas with a small scratch counterexample. Check conditional wording and linked references before reporting defects or absence; distinguish source contradictions from version-specific failures that require execution.

## Structured research migration

Follow [the migration and reconstruction workflow](references/structured-migration.md) when importing or auditing a research library. For a PDF/EPUB transition, use its [source-format upgrade recipe](references/structured-migration.md#change-source-formats-without-rewriting-legacy-evidence) before publishing new citations.

- For migration, start from a complete source inventory and compare every eligible substantive unit with the target; representative queries supplement full coverage. For ongoing research, query existing identity, facts, evidence and links (including pending/rejected and earlier/future records) before inserting. Reuse equivalent claim/evidence IDs and add justified subject/scene links; split multi-fact passages while sharing evidence. Preserve actual state changes and conflicting accounts separately: preventing redundant data must not erase history or ambiguity. Carry claim scope through statements, predicates, comparison keys and values: use neutral labels when identity continuity is unobserved, and qualify counts by the observed region and time, because consumers may ignore prose caveats. Make concerned-subject lookup links explicit when a publication includes other people or objects; require the actual owner/relation endpoints, but do not automatically attach the lead character to every fact. Represent an appearance comparison once and link both compared subjects rather than adding its reciprocal paraphrase; do not misuse whole/owner/location roles to avoid a real missing endpoint type. For a joint description, preserve the group as owner and use source-supported, observation-specific member lookup links rather than duplicating an individual fact for each person. Verify that an audit’s normalized records actually implement its reuse recommendations: a new-observation label alone cannot prevent different normalized values from creating duplicate facts. Retain differing source modifiers on their actual observation points without inventing continuity. Register source-attested short-name aliases for named actors: first-word fallback can collide with owned-object or group labels. Preserve genuine shared-name ambiguity instead of guessing an identity by type. A shared publication or paragraph does not make another person's clothing, remembered traits or literary imagery a lead-character body fact.
- Separate lossless preservation, structured reconstruction, and semantic/source verification. Do not call a migration complete merely because original prose is archived or selected scenes pass; close every required content/relationship check or enumerate the remaining gaps.
- Require database-only reconstruction to return substantive content, citations, speaker/viewpoint, story-time qualifications, conflicting accounts and adaptation status, not just paths back to original files. Test in an isolated directory without those files. When assembling reconciliation inputs, retain native locations, rationales and provenance for useful/duplicate reviews alongside new findings. Resolve every referenced finding's own work/source identity: a native review-point locator does not relocate cross-work comparison findings into that book. Preserve out-of-assignment cross-work references in an explicit comparison queue instead of silently dropping or backdating them. Require dispositions for both assigned finding IDs and native review-point keys: reused IDs may hide distinct observations. Review each point's actual excerpt, speaker and time before accepting support. For repeated observations, test each attested point and the gaps between them: neither duplicate claims nor an invented continuous interval repairs a query that loses later direct evidence. A descriptive fact's validity interval does not automatically extend an observation-specific wearer, carrier, member or user lookup: an object can retain its property after the related actor changes. Test the owner and former/current related actors across that boundary, preserving intrinsic comparison endpoints when the reviewed comparison itself remains true. When an actual intervening change is shown (worn → dropped → worn), preserve the distinct validity intervals; an exact-observation fallback must not bypass a known end. Follow the observation-point gates in the migration reference before changing shared retrieval behavior.
- Reconcile bundled assertions clause by clause before retiring the bundle: map every substantive clause to reused/new knowledge, a scoped unknown, a justified rejection or an explicit unresolved remainder. An archived paragraph or a smaller pending counter does not prove semantic completion. When retaining an ID for a narrowed surviving clause, document that choice and preserve the prior wording and links; give the other independent clauses their own records or explicit unresolved dispositions. Create a new ID for an unrelated fact rather than recycling a convenient rejected record.
- Require an explicit supports/conflicts/context decision for every reviewed claim–evidence link; a missing relation must fail closed rather than default to accepted support. Respect support-specific review flags: where the schema reserves accepted for supports, retain contextual evidence as context with pending/rejected full-claim support rather than weakening the trigger. When a reviewer aggregates several quotation fragments under one source-block key, resolve each claim to its actual supporting excerpt, speaker and context before importing; a shared block is not blanket support, and a fragments array is not one contiguous exact quotation. Use context for a shorter passage that is merely consistent with a stronger assertion; let the explicit direct statement support that assertion. Preserve the surrounding question/answer to establish the referent, without pretending the excerpt states every clause. Re-review support after semantic changes while preserving explicit conflict links. When historical fact/support rows are retained, require active queries to follow both the current accepted review and the current candidate–fact binding; changing a review or remapping a candidate must not leave stale support visible. Test withdrawal and remapping separately, preserve prior review metadata, and report active facts separately from archival table rows. Keep shared passage observation, speaker/context and revelation metadata consistent across uses; a missing claim anchor must not erase a known source-event anchor. Put claim-specific reasoning on the link, not the shared passage. Expose supported applicable facts separately from uncertainties and adaptations, retaining attributed/inferred classifications.
- For a frozen, source-reviewed text repair, compare complete permitted clause strings and mutation-test contradictory additions; required-substring guards can admit mutually incompatible prose.
- Treat helper report outputs as real writes: prefer fixed destinations, reject source/proposal aliases before writing, replace atomically and recheck protected inputs after the final write. Reject unused positional inputs for write commands: a fixed report can still alias a selected protected input, and a post-write hash failure cannot recover overwritten bytes. Retain that same-path regression.
- Treat approval of a data-model example as authorization to implement its structure, not approval of the example's hypothetical creative choices; keep those choices proposed unless separately accepted.
- When asked whether data was moved, answer factual-content preservation separately from structured-query readiness and semantic verification; pending review does not by itself mean the content is absent. When asked about retiring Markdown, inspect actual eligible content, external prompt artifacts, references and recovery rather than treating the whole folder as one disposable unit. Preserve originals until the applicable retirement checks and authorization are satisfied; do not require relocating prompts that the user wants to keep in their existing folders.
- When asked what a database query returns, execute the real read-only query and show representative actual records with IDs, citations, applicability and support-review status. Count supported results separately from archived candidates; assess whether those supported results satisfy the intended output. Disclose whether a displayed prompt was imported or derived from facts: stored prompt prose is not reconstruction evidence.
- Report concise final persisted dispositions, concrete corrections, tested reconstruction dimensions and exact unresolved work. Distinguish superseded bundles from false assertions, processed records from active reviewed facts, and unresolved baseline records from newly discovered review gaps. Assert that every mapped survivor remains active; a self-rejected target can silently remove a supported clause while checks and processed counts still pass. Source tags and successful SQL queries do not establish canon.
