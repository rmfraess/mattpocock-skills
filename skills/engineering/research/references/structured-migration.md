# Structured research migration and reconstruction

## 1. Establish the baseline and source boundary

Read the governing research contract, target schema, query code and existing importers before changing the store. Capture `git rev-parse HEAD`, `git status --porcelain=v1 --untracked-files=all`, target-library fingerprint and a recoverable copy. Inventory tracked and untracked research, root source manifests/maps, referenced assets and external leads; explicitly account for exclusions such as target tooling, generated audit output and Git internals. Hash original bytes before work and compare again at acceptance. For newly authored byte-fingerprinted replay inputs, establish their Git newline policy before registering the hash: inspect `git check-attr text eol -- <input>` and use a file-specific `-text` rule when exact bytes must survive checkout. Keep this protection scoped to the new input; changing a Git setting later does not repair an already mismatched artifact.

Treat the underlying book/document corpus as authority, not as a requirement to research every uncited narrative detail during migration. Distinguish migration coverage of existing project research from completeness of the original research search.

## 2. Compare source content with the actual database

Read every source, then classify substantive paragraphs, bullets, table rows, review decisions and supporting artifacts against the storage boundary. Inventory image prompts too, but designate their bodies and generation instructions as external output artifacts rather than research to import. Assign stable source-unit locators and retain factual section context. Compare eligible units with claims, evidence, chronology, relationships, unknowns and decisions. Identify missing content, path-only provenance, unsupported claims, duplicate passages, overbroad links and prompt prose incorrectly admitted as knowledge.

Do not mistake a lossless prose archive for scene-ready semantic records: a bundled row may mix observations, hearsay, inference and proposal or have unresolved applicability. Preserve the row, split useful clauses where verified, and keep remaining interpretation gaps explicit.

## 3. Import without authority inflation

Reuse the existing schema and standard-library SQLite tooling; add only structures needed by the requested queries or coverage proof. Keep the relational store for local evidence/time/review workloads; knowledge-oriented content alone does not justify a graph or vector service. Verify native full-text search in an in-memory SQLite FTS5 probe before adding search; do not add it merely because it is available. Reconsider the engine only when measured traversal requirements or concurrent remote writers warrant it.

Refine meaning with one atomic claim per supported property or subject–predicate–object relation, reusing existing evidence and validity records. Give scene containers explicit location/anchor, evidence-qualified participants, and actor/recipient roles for linked actions or dialogue; scene membership does not make every participant the owner of every claim. When rebuilding links after a split, preserve distinct source scenes within a chapter and regenerate actor/recipient roles from the corrected assertions; chapter-wide routing can move a quiet recollection into a later battle. Represent unknown values as unknown, not invented defaults. Preserve contextual paragraphs alongside these records rather than forcing every source sentence into an ontology.

Validate in memory or a new output file before replacing the active library. Refuse accidental overwrite and duplicate application; verify a recovery copy before authorized installation. Keep newly authored replay payloads patchable: format nested source audits and candidate arrays across readable lines instead of one enormous JSON line, because truncated reads and whole-line diffs can hide the field being reviewed. Complete semantic and phase-anchor review before pinning their bytes.

Store eligible research text/bytes or a reconstructable representation with hashes. For database-only operation, embed factual context and necessary reference assets, not downstream image prompts. Do not embed an entire mixed document to circumvent the prompt exclusion: retain its factual units with original line locators and keep the original document as an external path/hash reference. Keep the original fingerprint distinct from hashes of selectively retained text; never label sanitized bytes with the original SHA-256. Hash-only image references prove provenance, not database-only visual reconstruction.

Keep claims, exact evidence, original research assertions, creative decisions and review state separate. Never populate an exact-quote field with a ledger paraphrase or upgrade a source's `[CANON]` tag through parsing alone. Unknown historic search/approval dates stay unknown; migration time is not the original event date.

Verify each short PDF quote on its physical page and verify chapter membership independently within its component work. Parse every citation token, including comma-separated page lists and ranges, so structured references do not drop later pages. A valid page range is not proof that the assertion is on those pages. Keep original malformed or conflicting locators intact and attach a verified correction overlay. Attach warnings to affected assertions, not only to a remote audit summary.

Represent a reviewed relation once with multiple explicit evidence links, not one relation row per supporting quotation. Preserve each passage's own speaker/context and supports/conflicts/context role; a glossary corroboration and an in-scene welcome cannot inherit one batch-wide attribution. Verify both the relation count and its distinct supporting contexts through the real query.

Preserve source viewpoint and speaker, including dialogue, recollection, dream and report contexts. Resolve each participant's embodiment separately in mixed-realm scenes: a realm label alone does not establish whether an injury is physical or transient. Keep observation time and revelation order separate from fact applicability; do not backdate a later description without recorded support. Resolve component work through its stored identity/read order, not its position in an enumerated source list. Assign a new quotation its reader sequence as well as its physical locator; a verified page with NULL revelation order still cannot satisfy a spoiler-boundary query. Place event anchors at the quotation's actual chapter/scene, not the nearby chapter suggested by an imported citation. Before freezing a publication input, inspect each reused anchor's label, ordering basis and neighboring phase anchors against the passage's before/after sequence; a chapter-wide anchor can already mean aftermath and misdate a pre-event action while all SQL range checks pass. Preserve broad legacy anchors only with explicit coverage limits. Do not assign global in-world ordering from book/chapter order where parallel narratives or recollections make that inference unsafe. Give explicitly sequenced local actions distinct phase anchors when they change equipment or bodily state; an encounter-wide anchor can otherwise make a weapon simultaneously held and lost. Preserve verified local observations at unordered anchors when cross-plot alignment is unresolved; this does not authorize a global snapshot, a numeric order inferred from publication, or an interval between observations. Match body/representation frames on both claim and observation anchor even when an accepted support link connects them; keep joint bounded reconstructions outside a direct-observation result. Use an explicitly qualified direct-source query rather than blocking knowledge storage or weakening global applicability guards. A single source block can contain both sides of a transition: bind each quotation to its actual before/after phase, and never let a pre-transition excerpt support an after-transition qualifier merely because its block key matches. A verb's starting text offset is not an action-completion instant: establish separate before, completion and after anchors where a clothing or injury state depends on them. Infer order or an exclusive end only from the supported sequence; coordinated descriptions can overlap. End a wearer/item association when removal is established, not the garment's intrinsic color or stain condition merely because it is no longer worn. Bound superseded conditions at the actual transition and test before/at/after it. Keep unresolved cross-plot ordering unknown; reject globally ordered reconstruction at such an anchor while allowing qualified encounter-specific retrieval.

Merge only demonstrably equivalent records. For identical source/page quotations, preserve all original provenance/context metadata and redirect every relationship before removing duplicate rows. Do not merge paraphrases or conflicting temporal states merely because their words resemble each other. If link meanings differ, retain the disagreement rather than silently selecting one. Link approved direction only to genuinely supporting scoped claims; a blanket link to every subject claim can wrongly include later states or unknowns.

### Change source formats without rewriting legacy evidence

1. Probe the live schema on an in-memory backup with a synthetic citation in the new format before authoring publication payloads; editing a schema file does not change a populated database's constraints. Inspect retrieval, duplicate checks and pinned historical audits as well as table definitions.
2. Keep each approved artifact/edition as a distinct source identity, preserving old paths, hashes, evidence IDs and locators. Keep physical PDF pages in their original field and require an approved stable passage locator for an unpaged EPUB. Retain format-specific validation so accepting EPUB locators does not permit a PDF citation to lose its page. Make absence explicitly false in SQL CHECK expressions, for example with `coalesce`, because SQLite CHECK accepts NULL results. Reject NUL explicitly before GLOB-based text validation; GLOB can stop at NUL, and default `trim()` removes spaces rather than every whitespace character. Test the chosen whitespace class and both insert/update paths with valid controls.
3. Where SQLite requires a table rebuild, migrate only the necessary tables under verified recovery. Refuse an open caller transaction; capture existing rows, inbound references, explicit indexes, views and triggers. Use a tested transaction sequence for foreign-key handling, copy rows with their original IDs, restore dependent objects and check foreign keys before commit. Restore `PRAGMA foreign_keys=ON` afterward. Verify the recovery checkpoint's promised header/configuration as well as rows and schema; a logical match can hide changed `user_version`. When byte-identical recovery is required, copy under a compatible SQLite read lock and verify the full checkpoint hash. Recreate explicit indexes only for rebuilt tables, because surviving indexes on untouched tables already exist.
4. Inspect work-order uniqueness before adding another edition. When editions must share a reader-sequence key, adjust and test that constraint rather than inventing a new book order. Keep genuinely unknown order NULL and expose its effect on spoiler annotations; artifact identity and work order are different properties.
5. Make duplicate-location checks format-aware: group PDF quotations by their actual page and unpaged quotations by their stable passage locator. Grouping all NULL-page quotations together can falsely merge distinct occurrences. Preserve exact legacy coverage/inventory assertions for their historical source/run, and validate the new run separately. Keep historical PDF-only importers explicitly guarded against enriched libraries rather than silently rerunning their destructive merge path.
6. Verify schema migration separately from fact publication: compare all original rows/links and dependent objects, reopen the saved candidate, run integrity/FK/retrieval regressions, and reapply with no further delta. For standalone installers, export the pinned checkout plus only the declared delivery files through a private Git index and exercise the real CLI **and the declared tests from that export**; an in-tree suite can hide omitted untracked dependencies. Include source readers/manifests, and retain disk-drift, writer-lock, backup/readback and no-op replay probes because in-memory tests skip disk-only guards. Test valid PDF and EPUB evidence, missing/wrong-format locators, duplicate versus distinct occurrences, shared edition order and future-state exclusion. A passing schema-copy test proves preservation and compatibility, not research acceptance or installation in the active library.

### Prepare bounded semantic reconciliation inputs

1. Freeze a fingerprinted input snapshot containing the assigned finding IDs, the relevant comparison inventory and native useful/duplicate review points from earlier passes and continuations. Preserve each point's source identity, locator, text, rationale, referenced finding IDs and original review provenance. Resolve coordinates from validated original source keys when optional document/block fields are absent; compare the collected native-key set before dispatch so older review schemas cannot silently disappear. Keep self-reported review status distinct from parent acceptance.
2. Group repeated native locations without discarding their separate review records. A target may concern adjacent text, multiple speakers or another fact in the same block; retain it as a candidate support location, not automatically an accepted observation. Do not build reconciliation inputs from new-finding rows alone, because reused IDs can otherwise erase later evidence.
3. Pilot reconciliation independently of collection. Assign coherent event/state clusters sized by distinct evidence contexts and substantive clauses, and provide the broader candidate inventory for cross-shard equivalence checks. Enumerate both assigned finding IDs and native review-point keys; unassigned records remain comparison context, not completed reviews.
4. Inspect each returned component's actual keys, collection types and support/context references before writing the assembler; worker schemas can differ even under one assignment contract. Normalize those shapes once, coalesce shared subject identities against the baseline, and preserve explicit one-to-many key mappings when the parent splits a recommendation. Check both existing and within-payload anchor identity/label collisions before pinning bytes; coalesce only a genuinely shared event/container, not distinct observation phases that happen to have similar labels.
5. Require a disposition for every assigned finding and point. For retained evidence, select an actual short quote and resolve speaker, observation time, applicability and supports/context/conflicts. Verify exact sets, fingerprints and quotations separately from semantic acceptance; a generic rationale or complete ID ledger does not prove the contextual work was done. Keep recommendations versioned when new searches add pending scope, then have the parent reconcile overlapping proposals before publication.

### Incrementally build knowledge without duplicate accumulation

1. Resolve existing subjects, aliases, sources and scene/anchor identities before assigning IDs. Query every related claim through subject links, property/relation endpoints and scene roles, including pending/rejected and outside-time records. Production snapshots deliberately filter records, so they cannot alone prove a finding is new. Search both structured predicates and legacy prose for semantic equivalents; exact wording is only a candidate-finding aid.
2. Compare subject identity, property/endpoints, value, applicable time, classification and speaker/observation context. For an equivalent assertion, retain its ID and add missing evidence or links. Test the complete existing statement before attaching support, including its time qualifier: a later matching trait does not necessarily support an opening-scene assertion. Keep such evidence contextual unless earlier applicability is established; represent a distinct attributed account separately. For a genuine correction, preserve prior wording/provenance in review notes and re-review affected support. Link qualifier-only edits and explicit-unknown corrections to the specific new research units that justify them, while retaining their original unit links; a publication-level audit alone leaves claim retrieval without the correction's source context. Assign new IDs to unrelated facts: changing a rejected character record into an environment fact leaves old subject/scene/provenance links attached to a different meaning. For actual world changes or conflicting accounts, retain distinct qualified states rather than overwriting history. Avoid a uniqueness rule on subject/property alone: it would reject legitimate changing or disputed values.
3. Inventory each substantive clause before splitting a bundle, then assign its disposition: equivalent fact reused, new supported fact, scoped unknown, justified unsupported/nonknowledge rejection, or unresolved remainder. Map every clause to its resulting record or reason; leave the bundle unresolved when a substantive remainder is merely archived. Distinguish superseded bundles from false assertions in reports even if both use the schema's rejected status. Share verified evidence and original context across atomic claims. Reuse one fact across justified subjects and scenes through links; scene membership never widens validity or proves that every participant owns the assertion. Inspect existing role/endpoints before conflict-handling inserts; silently ignoring a different actor or recipient hides lost context. Surface schema limits instead of duplicating facts to bypass a key. After atomic splits, compare old and new clause meanings explicitly, including context-only entries: retained raw source text does not prove their disposition survived. Preserve conditionality, modality and explicit negation or causal exclusions in those paraphrases; test removal or weakening of each material qualifier, because shared keywords alone do not establish equivalent meaning. Recheck old support edges as well as new groups; adding a correct atom does not repair an older overbroad edge. Rebuild concerned-subject lookup links separately from ownership and dialogue roles, and derive scene roles from the evidence’s actual current or historical frame.
4. Apply a targeted transaction with foreign keys enabled and a captured before-state/recovery path. Insert newly resolved reference entities before corrections that point existing facts at them; otherwise a valid ownership correction fails its foreign key before the later subject-insert phase. Preserve unrelated earlier publication plans when changing write order, and verify every earlier input-bound manifest rather than regenerating their hashes to accommodate the change. Bind both the decoded payload and its raw bytes to the reviewed input; checking only the raw hash lets an API caller alter the parsed dictionary while passing the original bytes. Bind the full persisted verification plan and target-ID maps to reviewed authority too: a mutable database marker cannot define its own expected coverage. Include the reviewed reused source, claim, property and anchor rows in that plan as well as changed/new rows, because a stable ID does not prove its content still matches. Test empty/omitted checks, recomputed row hashes and remapped IDs through the standalone database-only audit, not just the writer. When auditing a named publication, bind the selected marker key/path to the payload's reviewed profile; a different individually valid publication must not satisfy that check. Update equivalent knowledge before adding new claims; use idempotent inserts only for genuinely missing equivalent links. Avoid entity replacement that deletes/recreates stable IDs. Reset stale support acceptance after changes to meaning, classification, time or evidence relation, preserving existing conflict relations unless their rejection is explicitly reviewed. Require every ledger evidence entry to name supports/conflicts/context; validate the complete ledger before mutation so missing relations cannot become accepted support through importer defaults. Check that each cited passage supports the actual clause: a room count on a damage page is contextual evidence, not proof of village destruction.
5. Capture immutable original unit-to-claim links before applying mappings; use that baseline for both publication and preservation checks. Reading links while adding them can propagate newly acquired units transitively through another mapping, falsely widening provenance. Compare relationship rows by their complete primary key: indexing claim–evidence rows by claim ID alone collapses multiple passages and corrupts delta verification. Derive composite keys from the live schema, such as `PRAGMA table_info`, rather than assuming the first column is unique. For intentional updates, allowlist changed columns as well as target keys; permission to revise a note must not silently permit changes to ownership, source endpoints or temporal bounds. Inject a failure after both corrections and insertions and require rollback to restore the old rows and remove the new ones; an insertion-only test does not exercise a mixed delta. Reopen the persisted delta and reconstruct every affected subject/scene, including before/at/after state changes. Reapply the same input on a separate SQLite backup and compare exact logical rows, IDs and relationships, not only counts. Enumerate application tables from the live schema and assert the comparison inventory covers them all, explicitly separating virtual-table shadow storage; a hand-maintained table list can omit evidence links while reporting a misleading pass. Compare installed rows with the verified candidate using the same captured review timestamp; a timestamp difference must not bypass equality. Verify one fact can serve multiple applicable scenes without copies, while future/uncertain applicability remains excluded from supported-now output. Preserve all original source and unrelated work; report reused/updated/new IDs and remaining gaps rather than a raw inserted-row total.

## 4. Verify the entire inventory

Compare every eligible persisted artifact hash and reconstruct retained text in original order. Account for every original line as preserved research or an explicitly excluded output-artifact range; selective units need not reconstruct a complete prompt-bearing document. Verify unchanged non-prompt units and reviewed factual extractions separately. Compare every stored search-matrix cell with its original value, including zero-hit cells; do not infer useful/duplicate/false-positive dispositions from raw or vaguely labeled relevant counts.

Separate passage acceptance from claim-specific support review: reusing an accepted quotation must not promote unrelated or bundled assertions. Keep semantic acceptance on the evidence-to-claim relationship; implied wording such as “extra shirt” supports a reasoned inference, not a directly observed garment. Preflight shared passage metadata across the ledger: reject inconsistent non-null source-event anchors, speaker/context or reader sequence, and require an explicit correction basis when changing established metadata. Preserve a known observation anchor when a contextual reuse supplies none; assign new quotations their position-derived revelation order. Add events using the existing field schema and local ordering domain rather than mixing incompatible sequence scales. Sweep active blockers, validity bases, link limits and disposition rationales after support changes so stale instructions cannot resurrect rejected support or manufactured conflicts. Otherwise ledger processing order can silently change every claim sharing that passage.

After applying all dispositions, assert every atomic survivor and mapping target is non-rejected, every retained survivor has its intended final status, and every original substantive clause still has a live target or explicit unresolved/rejection reason. Test self-rejected targets, context-only citations, preserved source-level conflicts, known anchors reused without an anchor, and missing revelation order. Compute reviewed counts from final rows, not the list processed before later dispositions; account separately for baseline reviewed/superseded/unresolved records and newly pending corrections.

Verify the complete targeted meaning against the reviewed input: claim ownership, predicate/endpoints/value, temporal bounds, passage metadata and every evidence-link relation/review state. Stable counts, valid quotations and successful replay alone can miss a wrong predicate or unrelated supporting passage. On a disposable candidate, deliberately substitute a different valid predicate and swap in unrelated accepted evidence; require verification/reapplication to reject each corruption, then roll back the probes and confirm the candidate is unchanged. For context-only imports, remove an essential applicability qualifier, such as interior-only exposure or an unverified neighboring surface, while recomputing its metadata hash; require the retained checker to reject the missing qualifier itself, because a stale-hash rejection does not prove semantic validation.

Fail closed when optimized Python would disable assertion-based migration or acceptance checks; never print PASS after skipped validation. Accept cached external evidence only when bound to an independently verified retrieval and fingerprint, not merely because a supplied snippet contains expected words. Check source metadata against the original publication, including interviewer and date. Do not treat a successful fetch, large `char_limit` or absent truncation footer as proof of completeness: verify the question and required quotation in the actual returned body before accepting a cached source. If extraction omits either, inspect the direct page DOM, preserve that actual retrieval and verify its fingerprint; hashing an incomplete extract does not recover the missing evidence. Pass a cached artifact path as an execution argument rather than embedding a machine-specific scratch path in the durable ledger.

Run `PRAGMA integrity_check`, `PRAGMA foreign_key_check`, project temporal-range checks, orphan/provenance queries and exact-duplicate queries. Reopen the saved database read-only and repeat acceptance checks. Count and aggregate in code, not manually. Record unresolved semantic review, inaccessible primary provenance and unrepresentable content separately from imported coverage.

Scope each preservation check to the delta it proves. Compare untouched source units, citations, approvals, coverage and assets exactly; verify intentionally changed claims/evidence against the reviewed reconciliation ledger. For additive publication, extend pinned inventory expectations with the exact new artifact path/hash and publication marker while retaining the original baseline assertions; merely replacing a count hides inventory loss. A historical cleanup test requiring all fact tables unchanged cannot validate later legitimate research updates. Keep that original cleanup regression for its own stage, then run the current prompt-boundary scan and retained-text hashes on the reconciled library rather than weakening the old test or treating its expected mismatch as corruption.

### Remove previously imported image prompts

1. Inventory every copy before mutation: prompt decisions, claims imported from mixed instructions, fine-grained units, coarse archival sections, original-file BLOBs, embedded approval text, notes and generated audit exports. Inspect full file/section context; matching the word `prompt` alone would delete legitimate provenance, paths or factual summaries.
2. Use explicit reviewed section/line boundaries. Keep factual stage summaries and evidence even inside a prompt-named file. Extract factual clauses from mixed geography/instruction paragraphs, preserving citations, qualifiers, chronology and pending status; do not delete or canonize them with the surrounding instructions. Retain actual creative approval/supersession separately from prompt wording.
3. Build a new candidate with foreign keys enabled. Remove pure instruction rows and dependent links in safe order; reconcile any selected source-supported claim before deletion. Remove duplicated prompt prose from approval-copy text without deleting its independent acceptance statement. Set whole prompt-bearing document payloads to NULL with external disposition, original path/hash and explicit exclusion ranges; do not retain a sanitized payload claiming the original fingerprint.
4. Verify against the pre-cleanup library: source/evidence/coverage/time/scene records and unrelated claims must match; retained research units must be unchanged or match reviewed factual extraction. Record stable IDs, exclusion ranges and hashes, not prompt bodies, in cleanup metadata. Test repeat application and tamper rejection.
5. Scan every TEXT/BLOB field for the excluded substantive prompt fragments, not only query output. Use `PRAGMA secure_delete=ON` during removal and compact the saved candidate with `VACUUM`; scan the resulting file bytes to check deleted prose is not left on free pages. Keep recovery checkpoints clearly historical: they may retain old prompts and must not masquerade as the active library.
6. Update the owning importer, acceptance expectations, inventory dispositions and readable reports. Exercise the full rebuild path to ensure it does not reintroduce prompts. Do not leave a test demanding the deleted prompt or claiming full-byte preservation of intentionally external artifacts. Reopen/install through the normal baseline/recovery checks, rerun real scene queries and verify original Markdown remains unchanged.

## 5. Exercise database-only reconstruction

Expose a query/CLI that returns facts plus their internal source context, citations, classifications, applicable/uncertain status, participants and relation roles, conflicts, approved/proposed decisions and gaps. Unknown dimensions must remain unknown; do not fill absence with plausible game detail.

For a publication-scoped source view, restrict returned evidence to the exact reviewed claim–passage pairs and the selected representation frame; separate claim and passage allowlists do not authorize their Cartesian product. When a result includes other actors or equipment, expose actual owner/object IDs and label a shared event frame honestly rather than presenting every row as the lead character’s anatomy. Reconcile contained excerpts at the same source point before freezing: different support/context roles belong on claim links, not duplicate passage records. Keep frame keys consistent between claims and anchors rather than independently paraphrasing them, because an exact-match guard can silently exclude an otherwise valid observation. Reconcile every selected claim absent from the narrow view by its actual exclusion reason, and retain a separate qualified inventory for memories, dialogue-only excerpts and undated reference material; do not weaken a witnessed-state query to make all published records appear. Keep other historical supports in the library, but do not silently include them in this view; reused claims may carry accepted links outside the publication.

Select related claims through actual relationship endpoints and scene links, never a hard-coded lead-character ID. Normalize role vocabulary at ingestion and verify every stored role is represented by query output. Associate binary artifacts with subjects explicitly; joining ownership only through text units drops images that have no text records.

Gate the supported-now section on established applicability, claim review, verified and accepted supporting evidence, classification/tier consistency, and reviewed claim–evidence support links. An accepted passage does not prove every claim linked to it, and context/conflict-only links are not support. Return unresolved timing, conflicting accounts and qualified observations separately with reasons; retain approved decisions with uncertain timing outside the applicable-approved section. Preserve the classification of attributed claims and bounded inferences even when they pass the gate.

Test the gate with synthetic records confined to memory: an independent non-lead-character scene fact, accepted passage with pending support link, conflicts-only evidence, unknown value, expired/future state, and approved versus merely proposed choices. Test binary artifact enumeration and quotations on both sides of a same-page chapter transition; a page-wide last-header lookup can mislabel a quotation without breaking an exact-text check.

### Recover repeated observation points without inventing persistence

1. Keep one atomic property claim with separately dated evidence. State the property, not a conjunction such as “has this equipment at event A and event B”: either passage supports the property at its own event, but neither alone proves the conjunction. Review the whole claim at each proposed observation point; metadata cannot establish semantic applicability.
2. First use the existing temporal model. If unknown-end lookup loses a later direct observation, permit only a narrow exact-point fallback: reviewed `observed_book_fact`, resolved start no later than the target, `end_status='unknown'`, and one matching support link with exact observation-anchor ID, Tier 2, verified locator, accepted passage, accepted claim-specific support with reviewer/time, and direct waking-scene/narration context. Require all fields on the same link. Leave stored bounds, ordinary interval logic, decisions and conflict handling unchanged; fail closed when the schema lacks support-review fields.
3. Return the matching evidence IDs as the point-applicability basis. Do not widen the interval between sightings, override a known end or ongoing horizon, backdate before the start, or automatically apply this fallback to dreams, memories, reports, dialogue, attributed claims or inferences. Preserve the stricter production gate: another qualified or conflicting supporting passage may still exclude the claim from `supported_now`.
4. Test both observed points, the intervening gap and later gap; test missing/wrong anchors, unknown/future starts, pending support, qualified contexts, mixed support, conflicts, known-end and ongoing boundaries, and reader-cutoff annotation. Inspect fixture constraints first: an accepted non-support link or duplicate ordered anchor may be structurally impossible rather than a useful negative fixture.
5. Compare old and new lookup results over the existing library's claims and ordered anchors before installation, not only the new subject. Inspect every changed result against its source, run existing regressions, and keep unrelated persisted rows unchanged.

Use representative scene and character cases covering appearance, equipment, actions, dialogue, locations, spatial relations, motivations, chronology and context. Include negative checks: later construction/marks must not enter an opening applicable set, dream observations must not become waking conditions, and attributed accounts must retain their speakers. Test both a character lookup and a scene lookup so participant relationships are exercised in both directions. When reviewing an alleged future-state leak, pair a later-revealed fact explicitly about the earlier event with an actual later bodily/equipment change: the former may be supported at that earlier event, while the latter must remain excluded. Test both relation endpoints and before/at/after anchors; first mention and player-facing spoiler limits are not substitutes for fact-validity tests.

Copy only the saved library and required query/test tools into an isolated directory with no original research or source corpus paths. Run the real reconstruction CLI there and parse its output; a code inspection or ordinary in-repository test does not prove independence. Run the full source-inventory audit alongside these tests, not instead of it.

## 6. Accept and report honestly

Persist application/readback and each verification phase separately with target/checkpoint fingerprints and execution-input hashes. Run a long suite as a separate job that records its exit status and discovered/executed test counts, so a caller timeout does not obscure which phases completed. Match delayed completions to their job ID, input fingerprints and pre-install/post-install phase; credit an already recorded result once, without reopening its gate or using it to certify a different phase. If a call times out, inspect the live process and exact persisted target before continuing. Reuse completed phase evidence only when its inputs still match, and resume missing read-only checks instead of replaying a completed publication.

Install only the verified candidate after reviewing its delta and preserving recovery. Immediately before installation, compare the active library with the captured baseline and reconcile any intervening writer's changes; replacing a stale snapshot can erase unrelated research. Verify the exact installed target; a tested scratch candidate is not the active deliverable. Leave originals unchanged unless their retirement was separately authorized.

If final readback exposes a publication error, correct only the affected records and links under a verified checkpoint, retain their prior values and the correction basis, and re-review any changed time/support metadata. Preserve an already registered immutable input with an explicit replay correction, or record an explicit input version; do not silently rewrite its fingerprint. Make fresh replay from the pre-publication baseline produce the corrected meaning, verify reapplication against the current library, and refresh the database-backed brief's IDs/anchors. A live-database-only fix leaves the next rebuild wrong.

Report migrated factual content, structured-query readiness and semantic/source acceptance separately. A preserved pending assertion is migrated content, not an accepted fact; review gaps do not justify saying the content is missing. If bundled assertions lack required semantic/time review, historical audit metadata is absent, or required direct provenance cannot be established, state which acceptance layer remains unverified. Do not relabel unknowns merely to satisfy a completion count.

For a requested commit, inspect the shared SQLite file's publication markers and pre-existing dirty state alongside the source artifacts. If it contains both this task's publication and earlier uncommitted research, explain the indivisible Git-file boundary and obtain scope confirmation before including the earlier package. Commit the corresponding publisher/input/brief dependencies together so persisted IDs and provenance remain usable. Stage new generated documents before `git diff --cached --check`; an unstaged diff check does not inspect untracked output.

For authorized Markdown retirement, inventory files and classify each as source/provenance, factual brief or downstream prompt. Verify preservation/recovery and all inbound references for the factual material; retain prompts in their existing character/scene folders when that is the user's chosen layout. Convert briefs into database-backed views or explicitly labeled snapshots with record IDs/reproducible queries and story anchors, rather than maintaining competing prose facts. Correct the knowledge store first and refresh dependent outputs afterward; separately stored prompt bodies are intentional exclusions, not lost migration data.
