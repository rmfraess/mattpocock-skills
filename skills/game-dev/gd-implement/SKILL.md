# Implement Game Work

Implement work already agreed in a spec, ticket, plan, or conversation. Do not reopen settled design. For work involving a live Editor, maps, assets, saves, retries, evidence, or acceptance, read the relevant sections of [GAME-DEVELOPMENT.md](../GAME-DEVELOPMENT.md), the project's effective instructions, approved direction, and version-appropriate engine guidance.

## Before editing

1. Fetch a supplied ticket reference through the configured tracker and state its title before editing. Proceed when it identifies one ticket unambiguously. Ask only when genuine ambiguity could select different work. When the user prioritizes getting the bones right, map the existing result to that ticket's acceptance before further art experiments. Finish the bounded foundation review first; carry optional refinement into an approved follow-on rather than letting plausible improvements silently expand the current milestone.
2. Capture the repository path, starting revision with `git rev-parse HEAD`, and starting worktree status. For a nested plugin repository, capture its revision/status separately. After owned child edits, reconcile the expected parent plugin-dirty entry against the exact child changed-file inventory; an identical-parent-status assertion can mistake that legitimate boundary change for unrelated work. Keep pre-existing and unrelated changes distinct from this task. When reusing preservation manifests, separate protected originals from previously authorized changes: compare changed sources against their verified built hashes, not their older pre-change hashes, and compare each asset against its latest accepted saved baseline. Diagnose mismatches by path before treating an obsolete aggregate assertion as new drift. When the user narrows focus, remove parked areas from the current acceptance gates without silently reverting their saved work; preserve mixed-scope changes, carry the narrowed priority into governing direction, and resolve separation before cleanup or publication. For environment work, resolve intended traversal and close/panoramic viewing conditions before choosing asset detail; a connected region does not automatically require close-up, traversal-ready treatment everywhere.
3. Before live Editor operations, verify the connected Editor's actual project path and authorized checkout, relevant map and asset identities, current unsaved state, available tools, and assigned Editor owner. Reconcile the latest assignment/handoff before the first Editor call, including read-only calls; finished journals or an empty active-run list show inactivity, not an exclusive reservation. Also check for concurrent agent sessions on the same project: recently active Hermes `state.db` `sessions` rows (`last_activity_at`, `cwd`, `title`). Another live session in the same checkout, such as a plugin install, makes ownership uncertain: keep to offline work and ask. If the handoff explicitly released ownership, resolve a new exclusive reservation rather than carrying forward an earlier same-session confirmation or writing self-certified ownership into evidence. If the approved change requires a build/relaunch, resolve the Editor reservation at task entry, before drafting code: request one bounded reservation covering preflight, shutdown/relaunch, tests, task-owned saves and final reconciliation. Continue isolated text work while a response is pending, but keep the implementation marked incomplete. Retain a granted reservation through that acceptance pass; release it at an actual handoff, not between implementation and its required verification. Reuse an explicit end-to-end grant rather than prompting again for each included substep. A worker's Git worktree does not redirect the Editor. Declare exact targets and relevant shared dependencies before dispatch, serialize overlapping or uncertain write scopes, and use an appropriate existing checkpoint or task-scoped recovery point. Preserve unrelated unsaved work.
4. Check the project's configured Editor MCP and listener before driving the desktop. If a configured server is not listening, diagnose its startup setting and use the engine's native start action to bootstrap the current session; for persistent access, set the version-appropriate project auto-start option and verify it on a fresh Editor launch with a real MCP tool call. Refresh tool discovery after the listener appears. Use MCP or VibeUE first for Unreal work. When a required operation is missing, check target-version official guidance, installed source and existing reflected tools before choosing between a small VibeUE extension and desktop input. An investigated extension is not an implemented capability: obtain any required source-change approval and prove it through a real build and the structured interface. Use desktop input only for a demonstrated structured-interface gap or explicitly native UI acceptance. For native-UI acceptance, perform the authoring actions through the actual controls; use MCP for setup and observation, not hidden repairs or synchronization that would make the ordinary workflow appear to pass. Establish one reversible authoring edit with exact value readback before running the full lifecycle: correct mode, tool and point selection alone do not prove editing works. If the intended transform/width remains unchanged, record an input no-op rather than diagnosing terrain or regeneration from a failed expectation that it changed. Record an input-delivery blocker separately from a game-system failure, and leave dependent acceptance unverified. Do not keep sending console scripts after MCP works. Before a C++ rebuild/relaunch, save the task-owned dirty packages and leave packages the Editor dirtied on load (unedited vendor MIs) unsaved. After relaunch, update the owner record's PID and re-run read-only calls whose outcome was reported uncertain. A relay-registered Editor MCP (the game-dev profile's `unreal-engine`) needs no reconnection; only a directly registered HTTP server parks during the rebuild, and then you re-enable it with `manage_connections` (action `enable`) after the readiness signal reports `mcpListening: true`.
5. If scope, target, ownership, or material starting state is unresolved, stop the affected operation and report what is missing. When the user asks to pause Editor use, end the turn at the next safe point with a short status, even if offline work remains. The pause usually means another session needs the project, and continuing in the same turn delays that handoff. Reuse existing approvals and project gates; do not add repeated permission prompts. When a live map is dirty or has an unexpected actor after the last verified save, identify the difference before Git handoff; an untracked on-disk map can look ready while the Editor holds unsaved, possibly user-owned changes. Once ownership is resolved, remove only the authorized accidental change and verify the intended saved state without discarding other dirty work. Run `git status` before every commit and treat a modified package you did not save as unexplained: compare its file mtime with the times of your own Editor calls (UE 5.9 keeps no per-call save journal). A save outside every agent call that wrote only the current map while other dirty packages stayed dirty matches a manual Ctrl+S (Save Current Level) in the Editor. Ask the user before staging or restoring it.

## Implement

Before the first non-trivial logic change, identify the caller-visible test seam and the smallest failing regression. Use the project's approved testing guidance; load `gd-tdd` for suitable specified behavior before implementation, not after drafting the feature. Reuse agreed seams without reconfirming each test. For engine lifecycle changes, keep the real integration check: exercise the built method through its intended structured interface, then verify its actual state effects. A declaration, static assertion or unexecuted test file establishes neither behavior nor a red/green result. If required execution access is missing, report that dependency and the unverified code status rather than presenting written changes as the deliverable. Do not force visual or content work into an unrelated code-test shape.

- Before implementing an appearance request (coverage, density, species mix, snow amount), compare it with the visual reference the direction doc names. If it moves away from that reference, say so in one line and confirm before building: a series of individually approved steps can drift far from the target, and the user then has to reverse accepted work. Before proposing any ingredient (a mesh role, texture, prop type), grep the spec, direction doc and evidence for it and for "do not restore"/"removed"/"rejected": a renamed version of a rejected role (for example ground mounds after rejected hummocks) re-proposes the same thing, so offer the direction doc's approved mechanism instead. Before Editor work on an agreed numeric mechanism, run its cheapest offline prototype, such as a DEM warp at the agreed scale, and compare the result with every agreed tolerance. If it breaks one, report the measured conflict, including your own planning error, with concrete alternatives; do not quietly retune another agreed value.
- For asset-led environment work, inspect the reference's required surface quality, seasonal form and silhouette before choosing implementation ingredients. Prefer suitable installed or already-owned Fab assets before procedurally generating substitutes; reuse is efficient only when the asset fits the intended viewing distance and realism. For an unaccepted visual ingredient, prefer a reversible small trial in the PIE copy before saving production packages; require a visible benefit at the intended player/cinematic distance, not just a close-up difference or higher instance count. Do not scale engine sample boulders into close gravel or keep polishing synthetic texture noise after the user identifies a substantial realism gap. Verify provenance separately for each visible role: Fab trees do not make the road or ground treatment Fab-based. Reuse the approved selection boundary and present one concrete intake decision when needed, rather than adding an audition gate. Follow [asset selection](references/asset-selection.md) for selection, close-surface fit, vegetation variation and seasonal assembly adaptation.
- Allocate environment detail by intended views: prioritize the playable route and close-shot sightlines, use simpler middle-depth assets, and preserve distant woodland silhouette, apparent density and seasonal continuity with economical representation. Choose transitions from actual visibility and screen size, not an invented fixed radius; a prominent object farther from the road can still require detail. Lower detail must retain enclosure and coverage without obvious seams or popping. Validate route-level and panoramic views instead of requiring unused deep-forest traversal, and add genuine crown/branch variants where rotation and modest scaling leave recognizable repetition.
- Treat the user's RAM headroom as an active operating constraint. Measure system available RAM and the owned Editor's working set before launch, regeneration, staging intake and PIE, then between heavy batches; use observed headroom and trend rather than inventing a memory budget. Serialize Editors and populations, reuse saved evidence when inputs are unchanged, and prefer a bounded local correction over rebuilding the forest. On memory pressure, reconcile active work and save task-owned changes before gracefully closing the owned Editor. Preserve requested density and verification; reduce representation overhead or concurrency instead.
- Work in small behavior slices and preserve the agreed outcome. For incremental visual feedback, edit the existing authoritative candidates/materials with the fewest necessary files and native features; do not introduce another generator, framework or population ledger when the existing one supplies the controls and checks. When the user asks to make an existing feature easier to see, change the requested surrounding contrast first, preserve the feature's mechanics/layout, and deliver one useful labeled before/after rather than expanding into final-art redesign. For an approved bounded appearance pass, finish any requested foundation checkpoint first, change one visual mechanism, rerun the affected persistence/contact checks, and deliver one useful labeled comparison for the creative owner's verdict; stop there rather than trying successive variants or expanding into production integration. Keep routine handoffs to the visible change, verification and remaining limitation. For Unreal Python placement, preserve an existing Transform's rotation/scale by updating its translation instead of reconstructing it with `rotation=t.rotation`: `MakeTransform` expects a Rotator, while Transform.rotation is a Quat. Convert native Arrays to Python lists before list concatenation. Treat array struct iteration as value copies: write edited vertices/transforms back by index, then verify saved geometry or collision; a successful mesh-save call can otherwise persist unchanged vertices. Verify StaticMesh persistence against the original authoring input converted to the engine's native storage precision; derive expectations before reading the saved result, reject a deliberate mismatch, and retain separate cold collision checks. Prefer exact native-precision comparison over adding an arbitrary tolerance; use the [mesh persistence recipe](references/unreal-captures.md#native-precision-mesh-persistence) when Python doubles feed float source data. For appended support strips, test downward rays and positive hit-normal Z before accepting winding: mathematical cross-product signs alone do not establish Unreal's front face. When an appended strip is underside-facing, select only its new triangle IDs with `GeometryScript_MeshSelection.convert_index_array_to_mesh_selection` and use `GeometryScript_Normals.flip_triangle_selection_normals`; never flip the accepted original mesh. A collision pass after flipping still requires a fresh normal-scale visual check. Flip only the new face selection if underside-only traces hit. When ground "looks flat", measure slope by distance from the road and each review camera's distance to it before adding relief: a relief road-fade can flatten exactly the band roadside views look across, and features under ~2x the Landscape vertex spacing barely render (larger ridges/banks do). For road-scale terrain, inspect the existing Landscape vertex spacing before sculpting: a coarse regional heightfield may need a small colliding detail-ground mesh, with the existing PCG grounding path extended to read that tagged surface. Check winding using top-down collision and an upward normal before re-grounding; visible triangles and collision flags alone are insufficient. Verify the live `Rotator` constructor order (positional values are roll, pitch, yaw) and read back transforms before saving; a visually plausible but misoriented actor can survive an otherwise successful save. For material-instance setters, read back the parameter instead of trusting a boolean return alone; a false return can accompany an applied value.
- For reference-led regional layout, establish full-scene land-use coverage from the approved camera/image before refining local patches: account for foreground, flanks, background and lighter transition zones between major biomes. Treat old proxy bounds as implementation baselines, not approved coverage limits. When the user rejects regional extent, reassess that whole composition rather than repeatedly enlarging the same local footprint; passing roadside samples proves continuity, not reference fidelity. Separate near, middle and distant landmarks, then distinguish connected core bounds from scenic backdrop. Reconcile a separate regional map as directional off-camera continuity unless its scale is authoritative; do not force every mapped landmark into the approved shot or silently promote an illustration to canon. Fitting named markers inside an arbitrary rectangle can preserve every label while producing the wrong scale and spacing. When the creative owner defers an area pending research or accepted imagery, preserve its reasonable reservation and useful generic placeholders, update governing direction and affected active ticket scope, then continue independent environment work. Do not treat guessed architecture as accepted design, enlarge placeholders merely for panoramic readability, or turn missing final detail into a blocker; retain the pass's physical connection and geometry checks.
- When the user reports a substantial remaining reference gap, compare the actual reference and latest persisted view before another mutation. Separate footprint/negative space, connectivity, cross-sectional volume, boundary smoothness and shading; preserve the dimensions the user already likes while correcting the rejected one. Treat rounded volume and irregular footprint as independent requirements: natural melt needs asymmetric retreat, broad bays and unequal lobes, not a regular oval with a noisy rim. When volume is accepted, reuse its shaping method and change the contour inputs first. For a coverage-only request, preserve the accepted profile, seed, material and clearance margins; tune the existing occupancy threshold before adding controls or rebuilding the generator. Define the percentage's domain and metric, distinguish a target percentage from a relative increase, and report the measured result rather than claiming the requested number exactly. Follow [projected-coverage calibration](references/unreal-captures.md#projected-coverage-calibration) for numerical fitting and validation. Larger or partly merged patches do not authorize a blanket, and accepted coverage does not approve flat geometry. Diagnose material/asset quality, physical landform, edge integration and composition separately; choose a different ingredient or mechanism where the current one has reached its visual ceiling, not another noise/density/tint pass. For a shape correction, establish a readable representative crown-to-edge view and demonstrate the benefit in a reversible small trial before full-region regeneration; greater peak height or triangle count alone is not visible roundness. Follow the patch-surface checks in [bounded mesh-shape refinement](references/unreal-captures.md#bounded-mesh-shape-refinement). Establish a comparison camera showing the reference's semantic location, such as the woodland exit toward fields, rather than claiming a deep-forest road view demonstrates the same composition. Surface-only authorization cannot deliver a protected descent, bank or forest-opening change: state the necessary bounded scope decision and continue only independent authorized work. When asked for a plan, provide an ordered corrective sequence with visible acceptance checkpoints, not implementation or a new ticket hierarchy.
- When feedback calls an approved visual reference into question, inspect the image, its controlling prompt, and source evidence **before** requesting regeneration. If the feature is already specified and visible in the reference, fix the implementation rather than moving the target; if the image itself is ambiguous, recommend a focused revision preserving accepted composition and unaffected details. Keep the original authoritative until the creative owner accepts its replacement. After acceptance, search project direction and active parent/child tracker bodies for literal old-revision paths; update only governing references, not historical evidence. Reconcile the generating project's README/label status and any generator that rewrites that status, preserving original image bytes and unrelated work. Read back an edited remote issue's exact body, and do not mistake approval of reference imagery for acceptance of the current in-engine result.
- For route blockouts, verify adjacent segment endpoints and road/river crossings numerically **and** inspect them from the approved view and overhead; connected transforms can still be hidden under solid proxy masses or visually read as the wrong road. Treat projected route overlays as explanatory evidence, not proof that the unannotated panorama itself makes a road legible or walkable. Inspect full-width ribbon triangle orientation and footprint: offset edges can fold around a bend tighter than the half-width while centerline traces pass. Broaden the join or use a simple landing rather than flipping faces to hide self-overlap. For reference-framed layout, material-pass comparisons, shader warm-up, bounded mesh-shape refinement, cook evidence, or scene-cost capture conditions, follow [references/unreal-captures.md](references/unreal-captures.md). For Generate-driven terrain relief (including terrain-first development with the road removed and rebuilt later), rock outcrops, residual snow, deadfall, floor clutter density, context-aware litter placement rules (banking against obstacles, species-matched litter, avoiding grass, melting-edge litter fed the forest's floor output), full grass cover kept off snow with a seamless snow edge, A/B/C colour variants of generated meshes and forest-floor material readability (contrast/variation before POM), follow [PCG ground generation](references/pcg-ground-generation.md).
- When the user prioritizes authoring editability, verify move/grade/width and explicit regeneration before surface polish; a curved baked mesh is not editable spline authoring. Explain which changes follow the route, which require Generate or rebuild, and which lifecycle cases remain manual. Frame review as acceptance of an editable foundation, not finished art; screenshots cannot prove movability or a profile they do not clearly show. Record foundation acceptance and deferred appearance work in existing project direction, then stop polishing that proof. A subsequent continuation authorizes the stated next bounded step, not unstated production migration. Reuse native facilities and follow [road-authoring conversion checks](references/unreal-captures.md#road-authoring-conversion-checks).
- Before fitting a reusable road profile into a protected existing route, compare both saved endpoint cross-sections with the proposed profile in the actual spline frame; matching control points do not preserve relief baked into source vertices. VibeUE ConnectSplinePoints invokes AutoCalcRotation on both endpoints: apply any required fixed endpoint rotations after all connections, then verify generated world-space join vertices and support rather than only source coordinates. When substituting an existing relieved mesh into a route-UV material, inspect and reconcile its UVs with the reusable profile's scale/orientation; inherited world-fixed UVs can create transverse bands even with correct collision. Resolve an incompatible fixed join before terrain or dressing work, and treat boundary adapters as a proposal until authorized and tested. A broad new detail tile must also clear every protected road footprint it covers behind those joins: include those roads in face-fit constraints and final grazing-depth checks, not only the migrated spans. When a bank supplies support within the contact gate, do not impose a redundant Landscape-only maximum-gap constraint that can make a valid downward fit infeasible. For an over-tight edited bend, prefer native Auto Rotate/tangent controls before per-point mesh lifts or per-section vertex work. Separate Landscape render-LOD burial from true contact with fixed-camera depth and collision checks; a small overview pass can miss outer-edge intersections. Dense near-end samples can leave one deformed piece while remaining covered by its neighbor: retain per-piece failures, then check the actual connected-road union before calling them holes. Reject a lift that clears pixels but exceeds the existing contact bound. For an authorized fixed-boundary correction, restore the native endpoint frame first and measure again before fitting support; prefer native setters and the smallest task-local terrain delta over new runtime code or an authoring framework. Use the [fixed-boundary support recipe](references/unreal-captures.md#fixed-boundary-landscape-support-fitting) only when native grading intentionally excludes those compatibility pieces.
- For narrow collision-draped road meshes, compare ground and overview rendering: Landscape render LODs can bury a geometrically continuous road even when collision agrees. Probe only route-local component detail reversibly, preserve heights, and use the minimum verified override for a coarse pass; record its scene-cost ceiling rather than claiming performance. After changing a StaticMesh BodySetup collision mode, save/reopen and exercise both simple and complex traces; existing components can retain stale physics state despite correct flag readback. For bounded dirt/stone/wear refinement and ground-matched shoulders, follow [road-surface treatment](references/unreal-captures.md#bounded-road-surface-treatment); separate shader relief from collision geometry and retain the accepted terrain/route baseline.
- Bracket Landscape data diagnostics with dirty-state checks: engine texture accessors used by height/weight readers can call `Modify()` even when only reading. Avoid that path for strict package-preservation work; otherwise flush only the authorized, semantically verified target package before handoff. Compare paint baselines and reloads through the same read path: the edit-layer region accessor and rendered-composite exporter can differ at blend boundaries without any paint change; do not rewrite weights to satisfy a mixed-path hash.
- Keep generated paint-source and capture filenames distinct on case-insensitive filesystems (`damp-mask.png`, not `Damp.png` beside `damp.png`); validate source dimensions and content hashes before import and delivery so a screenshot cannot silently replace the authoring input. Store the actual source-file hash separately from the composite-export hash: different PNG encoders can produce different bytes for identical decoded weights. Exercise rejection of a same-size wrong source before crediting the pre-import guard.
- For a new branch on sloping ground, sample the pre-road destination height and choose the intended endpoint grade/tangent instead of copying the junction Z: native Raise Terrain can otherwise build an artificial berm while traversal still passes. Verify the low-angle landform, actual support and re-grounded roots; do not hide the terrain to fix it. For native Landscape road splines, use exposed service info or C++ automation for active arrays and connection references; Python cannot read protected `ControlPoints`/`ControlPoint` merely by changing property spelling. Exercise generated meshes, old-footprint collision and clear-all Redo after native teardown; explicit targeted rebuilding can preserve Redo without an added transaction. Verify world points through the spline component transform: it cancels Landscape actor scale, while some service helpers transform through the actor instead. For a preservation-only conversion, preserve section UVs/vertex colors and disable terrain raise/lower and painting explicitly; do not turn that conversion precaution into a permanent grading restriction. For authorized editable road grading, prefer the target-version specialized Spline Edit Layer over stamping base sculpt, and prove abandoned-influence cleanup. Write nested mesh-entry structs back into their array, use `center_h=False` to retain the lateral origin, and verify generated components, width edits, bridge joins, saved reload and PIE collision. Test each protected route's components directly when crossings or compatibility joins overlap; a highest-hit road union can mask its missing collision or bad clearance. Keep joined-coverage checks separate from route-specific preservation. Distinguish baked conversion from layered authoring: moving points does not re-drape baked section relief or separate banks; enabled native spline grading updates its dedicated terrain layer, while forest clearance still requires the configured explicit Generate. World-position shader masks remain spatially anchored. After bends or width edits, test full-width section joins as well as centerline traversal: pinning endpoint widths alone does not prove matching cross-section heights or gap-free edges. Normalize lateral endpoint coordinates against native generated start/end scales to obtain the same world width on adjacent sections. For fixed-relief compatibility adapters, inspect native `no_z_scaling` and the generated Z scale too: scale-to-width normally scales Z, which changes a preserved source endpoint's relief; set task-owned entries appropriately and verify the entire world-space endpoint curve. Sample triangle interiors against the highest actual bank/Landscape collision, not just vertices; curved deformation and different triangulation can leave raised faces despite exact vertex seating. Retain a small distributed full-width regression in the existing checker. Compare exported shader text using normalized newlines; Windows file-byte hashes can differ from identical Editor text.
- For production promotion of a cloned Landscape, audit internal saved dependencies as well as top-level bindings: changing TargetLayers alone does not replace edit-layer/mobile weightmap allocations, and material assignment can leave internal MIC parents on the source. Use the native layer-replacement workflow and verify reference closure plus unchanged decoded height/paint after reload; never consolidate or delete protected source assets to hide stale references. Also rebind copied StaticMesh default materials even when component overrides render correctly. Follow [cloned Landscape promotion](references/unreal-captures.md#cloned-landscape-promotion) for the ordered native repair and persistence checks. For editable Landscape paint, verify persistent target-layer names and nonzero weights after reload, not just rendered colors. VibeUE material assignment can register only transient LandscapeInfo; register each LayerInfo with `LandscapeService.add_layer` before painting/importing, then save/reopen and read weights. When existing normalized paint must remain unchanged, use a non-weight-blended overlay sampled through `LandscapeLayerSample` and a simple Lerp; compare every protected layer before/after because adding another normalized layer redistributes weights. Insert broader ground coverage before localized stone/moisture overlays so it cannot swallow their accepted cues; inspect the saved graph's actual connections. Reuse existing detail samples rather than duplicating a surface stack. For coverage assessment and correction, follow the regional-paint workflow in [references/unreal-captures.md](references/unreal-captures.md).
- Preflight custom-material structs and pins before graph mutation: instantiate `unreal.CustomInput()` / `unreal.CustomOutput()` empty, set/read their editor properties, and resolve exported expression IDs through `MaterialNodeService.list_expressions().object_path`. Read Custom-node arrays with `get_editor_property('inputs')`; discovery listing an Editor property does not establish a direct Python attribute. Use `get_editor_property('input_name')` on its structs. Set the `inputs` list only on a node you are creating and wiring in the same script: Python cannot read a `CustomInput`'s wire, so rewriting an already-wired node's list silently drops every link and they cannot be restored from Python. To extend a wired Custom node, add a new Custom node that takes the old node's output plus the extra inputs and replaces only the target term (recompute that term exactly from the same inputs), then rewire the old node's single consumer to the new node and assert the old node's link set is unchanged. When the generating script owns every source of the node (its own parameter, WorldPosition and Time nodes), it can instead rebuild in place: restore the downstream links, delete the node and its owned sources (never shared engine nodes), and re-add it with the new pins; `ue-materials-and-shaders` (its volumetric-cloud-materials reference) has the steps. `MaterialNodeService.list_expressions` also lists nodes inside called material functions, so filter by `get_outer() == material` before picking a node by class; it and `list_connections` return nothing while PIE runs, so do graph lookups with PIE stopped. Keyword constructors and protected expression inputs such as Multiply.A are not reliable access paths. Use `''` for VertexColor's first native output rather than the assumed label `RGB`, then inspect the exported connection. If a connection call returns false or an assertion fails after mutation, export the graph and inspect the exact source/output/target/input before deciding whether the operation failed; the edge may already exist. Resume only reconciled missing work within the applicable retry limit, never recreate the already-added input or node.
- For material-service connections, use exact expression IDs from `export_material_graph`, not UObject names: ambiguous name suffixes can silently wire the wrong node. Native pin names can differ from exported display labels: pass `''` for the unnamed ComponentMask input in `MaterialEditingLibrary.connect_material_expressions`, then inspect the actual exported connection. Compile with the discovered native `MaterialEditingLibrary.recompile_material` API, but do not treat an empty return as success: it does not surface HLSL or function-link errors. After shaders finish, grep the log for `Failed to compile Material` naming the material or its dependants (a map's landscape MICs report under the `.umap`), ignoring lines timestamped mid-rebuild, and inspect a capture; a grey checkerboard means shaders are still compiling, not a result. Compilation/diagnostic calls can mutate state, so keep them inside the authorized material scope. For shared material logic, put one Custom node in a MaterialFunction and call it from each material. Callers link to function inputs/outputs by GUID, not name: once a function exists, edit its nodes in place (e.g. swap the Custom node's `code`) and never delete-and-recreate its graph, which silently disconnects every caller while they still compile. `delete_all_material_expressions_in_function` can leave nodes behind; delete via `get_material_function_expressions` one by one and assert none remain. A script that rebuilds a material's graph every run must itself insert the function call, or the next run drops it. In Custom HLSL, sample through `View.MaterialTextureBilinearWrapedSampler`/`...ClampedSampler` instead of per-texture samplers (landscape materials sit near the sampler limit), and define helpers as methods of a local struct. Build `Vector4f` and other struct property values by empty construction plus `set_editor_property`, like CustomInput. Save and explicitly reload changed material/instance/layer packages before validating persisted parameters and wiring; reopening only the map can leave edited materials resident. Reopen an unchanged map without saving it when the pass is material-only. When superseding provisional shading, update the existing validator to check the new shader and dependencies while retaining geometry, instance and scene-preservation checks; mark earlier shader evidence historical rather than leaving contradictory current claims.
- When creating StaticMeshes from mixed GeometryScript buffers, initialize UVs for every triangle (including appended pools/caps), even with constant-color materials. Run a whole-mesh UV projection/unwrap and inspect UV validity before saving; UE 5.8 can assert `NumUVs > 0` during the asset build when some sections have none. When replacing an already assigned StaticMesh, skip identical `set_static_mesh` calls and validate readback: the native setter returns false for that no-op, which must not trigger a duplicate save/recovery replay.
- When journaling unattended Unreal work with VibeUE, parse `start_run` and retain its identifier for later journal methods; passing the whole response as the ID leaves the run unfinished. Validate each method's actual response shape: the start envelope can use `runId`, while `get_run`, artifact attachment and finish return a run record using `id` and `status`, not the same envelope. Confirm attached paths and final status through `get_run` before retrying, because an incorrect key/success assertion can fail after the journal write already applied. Print only identifier, status and artifact count, not the complete event/index history.
- When appending a branch to an existing native PCG graph, mirror the working sibling's required input and terminal-output wiring before Generate; an authored candidate array and connected spawner input do not establish that the branch executes. Verify actual generated output, and retire corresponding fixed instances only after their replacement passes. For an explicit native PCG Generate loop, set both Generate On Demand and `regenerate_in_editor=False` on the task-owned component. On Demand alone can still refresh already-generated output after tracked Landscape edits. Verify actual generated instance records remain unchanged across a route edit, then use a separate explicit Generate and later-tick readback to verify clearance, abandoned-footprint infill and grounding. Reuse the production checker's serialized Transform3f readback for bulk skinned instances whose ID lookup cache is not materialized.
- For percentage-based vegetation revisions, distinguish the percentage's denominator from the species receiving additions: increasing total tree density using only Pines is not increasing the Pine count by that percentage. Resolve this before placement; preserve existing trees and reuse accepted assets and the current authoring representation. Prefer appending candidates to an existing PCG graph over another generator or new assets. Follow [incremental density revisions](references/asset-selection.md#incremental-density-revisions) for live baselines, planning and preservation checks.
- For assembled vegetation intake or seasonal adaptation, follow the [assembly workflow](references/asset-selection.md#assembled-vegetation-and-seasonal-variants). Keep vendor originals unchanged and runtime-feature enablement separate from intake approval. Reuse proven parts and native assemblies before expensive conversion; judge the actual rendered seasonal form, not a trunk-only fallback or successful material-slot readback. Disclose omitted detail and keep art acceptance distinct from production readiness.
- Keep live Editor control and mutation of its active project's assets with the assigned owner for the whole bounded inspect, change, save, and verify segment. Independent research, saved-snapshot inspection, isolated code and tests, and offline asset preparation may proceed separately, but must not control the Editor, write into its active Content tree, or trigger reloads. Transfer ownership only after saved changes are verified and the next owner reconciles current state.
- After a timeout or ambiguous operation, inspect the resulting state before retrying. Complete only reconciled missing work within existing retry limits, or report the unresolved state. Do not replay a potentially completed placement or write blindly. Persist aggregate measurements and an explicit failed status before the final acceptance assertion, so a legitimate scene failure does not discard independent passing evidence. Do not weaken an acceptance threshold merely because fixing a checker exposes a real content defect. When raising a roadside support bank, recheck road-edge triangle interiors as well as the original shoulder probes: interpolation can lift support beneath the road even when edited vertices lie outside it. Re-drape only affected sections and use denser face sampling before saved-state acceptance; collision success still does not clear visible surface discontinuities. Include the last fraction of an endpoint taper and the outermost road edges explicitly: regular longitudinal samples can miss intersections within centimeters of a protected join. If retaining endpoint vertices prevents clearance, report that bounded join/support decision instead of silently changing the accepted adjacent section or repeatedly lifting the entire road. When a lift reduces a rendered strip but exceeds the existing contact limit, reject it as a failed fix; restore only its recorded deltas and verify both interior/edge contact and package scope before proceeding. A less visible intersection is not permission to leave a newly raised road. When a protected join is involved, read its actual saved endpoint cross-section before fitting nearby interiors: pinning already-under-ground endpoint vertices makes a clear taper impossible. Distinguish legitimate exterior-of-ribbon misses from holes by sampling actual collision triangle interiors or joined native cross-sections, not assumed frame coordinates at the final fractions. If a failed trial changed mesh topology, restore the exact task-owned checkpoint packages with the Editor closed rather than trying to reverse only vertex deltas; cold-load and verify package hashes/representation afterward. Fit roads against their actual highest supporting surface, not Landscape alone: raised detail banks can intentionally sit well above Landscape. Before another vertex-only bank correction, project measured bad pixels onto actual saved bank triangles; faces crossing the ribbon can remain intersecting even when no editable vertex is beneath the road. Use that face evidence to bound a proposed split/fit, preserving the outer shoulder. After restoring saved assets externally, reconcile GameIQ too: save hooks can index rejected trials; inspect semantic differences and restore the verified pretrial index snapshot only when it would not discard unrelated index updates.
- For conflicting binary assets, follow an existing authorized resolution plan or pause the affected integration for a plan. Do not silently choose a version.
- When an Editor call returns False or does nothing without an error, grep the log for `Message dialog closed, result:`. Scripted calls, including deferred Slate-tick callbacks, auto-answer modal confirmations with their default (usually Cancel). One example is the asset-rename warning raised when a class default object soft-references the asset (seen for maps; ordinary assets rename fine by script; see [bulk asset rename](references/bulk-asset-rename.md) for whole-folder renames). Count that as a failed attempt rather than retrying it from another scripted context. Renaming or loading a map as an asset leaves it resident (`unreal.PythonTools.get_resident_maps()`), so relaunch before the next level change. Before moving an LFS-tracked package, run `git check-attr filter -- <new path>` and move its `.gitattributes` rule with it, because path-specific LFS rules don't follow the file.
- Apply line-numbered edit plans (triage tables, review findings) by matching each line's text from the snapshot that was numbered, never by number alone: another session can change the file in between and shift every later line. Verify against that same snapshot.
- `git lfs migrate import --include-ref=<branch>` also rewrites any other local branch on the same commit (including a just-made backup branch) and can leave pointer files in the tree. Back up with a tag or a noted SHA, run `git lfs checkout` afterwards, and check each blob's sha256 equals its pointer `oid`.

## Verify and review

Run checks required by the assignment and repository rules. During each behavior slice, run focused tests and typecheck after changes affecting types or interfaces, rather than after every patch. At completion, use the required checks. Use narrower final validation only when the assignment or repository rules explicitly establish it; otherwise run the full suite. Earlier results count only while their relevant inputs and environment remain unchanged. In a regenerate-then-check shell chain, never pipe the generator through `tail`/`head` before `&&`: the pipe's status is `tail`'s, so a failed generator leaves the previous outputs and the following equality check passes on stale files. Use `set -o pipefail` or assert the output's mtime/hash changed. Run repo offline numpy/scipy generators with `uv run --no-project --with numpy --with scipy --with pillow python <script>` so the result does not depend on which interpreter is first on PATH. Distinguish a map/dependency cook, a packaged executable, and standalone runtime evidence in the completion report; success at one stage does not verify the next. Report failed or unavailable checks honestly. When continuing after an issue-gap review, close the named evidence gaps before adding more content. For corridor or regional coverage, derive a compact section/asset map from existing saved expectations, reconcile its groups against the relevant total, and identify untreated or unverified boundary joins before choosing new authoring. Inspect those boundaries first; absence from the previous treatment report is a reason to inspect, not a reason to rebuild. Do not extend representative face-contact or appearance evidence to sections it never sampled. If current representative captures and saved-state checks reveal no material in-scope defect, deliver the review evidence without altering accepted assets; optional polish and wider-region work remain follow-ons.

For persistent content, save only task-owned changes and inspect the persisted result and relevant references. Compare sampled reload evidence by a unique semantic key, asserting key uniqueness and identical key sets before comparing values; native component enumeration order can change without changing geometry. Use a persisted route/segment identity plus sample coordinates when generated component names are unstable, and retain exact numeric comparison rather than weakening tolerances to hide ordering differences. Before switching maps after a native level export, set `AssetExportTask.object=None`, release the task/exporter and drop local World/actor wrappers in a completed call; a live task reference can trigger fatal World Memory Leaks during `load_map`. Native `EditorLoadingAndSavingUtils.save_map(world, new_path)` can save a duplicate while leaving the original current and the duplicate resident. Verify actual current/resident Worlds instead of assuming Save As switches maps; unload the extra package, release local Python references and verify no resident map before loading its saved path. Do not replay a successful save because a later current-map assertion failed. `reload_packages` on an asset modified in memory opens a modal confirm that blocks the game thread and hangs MCP: to revert an edited asset, restore it from Git and answer that dialog (check `gameThreadStallSeconds`; background `return` key delivery can land where clicks fail), or restore with the Editor closed. Avoid `reload_packages` on the current World to discard verification-only changes: live Python Package wrappers, including the reload argument list, can prevent old-world GC and cause a fatal World Memory Leaks assertion. Prefer a controlled relaunch without saving, and verify saved package hashes first. A force-killed Editor with dirty packages (including `BuildAndLaunchGame.ps1`, which kills the running Editor) opens a modal "Restore Packages" dialog on the next launch that stalls the game thread: the readiness signal stays on `/Temp/Untitled_0`, MCP never listens and `gameThreadStallSeconds` climbs. A normal `-Map` launch also publishes `/Temp/Untitled_0` first and rewrites `currentMap` once the map loads; treat it as the dialog only while the stall keeps climbing. Check for it whenever readiness stalls after a relaunch. Background clicks and Escape do not reach it; a foreground click on **Skip Restore** (`computer_use` with `delivery_mode='foreground'`) dismisses it, and the click can land even when the tool reports an error, so re-check health before retrying. Alternatively, with the Editor closed, move `Saved/Autosaves/PackageRestoreData.json` and the listed `*_Auto1` files aside (after confirming they list only task-owned trials), then relaunch. Prevent it by leaving nothing dirty before a scripted relaunch. When the user asks to see the work in the Editor, check the recorded PID's `editor-<pid>-health.json` first; between turns the Editor may have exited (no health file, log ends in `LogExit: Exiting.`). If it exited cleanly with git clean and no source change since the last successful build, relaunch with `-SkipBuild -Map <map> -WaitForReady`, verify the current map and an empty dirty list, and park the viewport camera on the changed content (aimed at a placed instance) before handing over. When your own long script wedges the game thread (MCP times out, `gameThreadStallSeconds` keeps climbing, the process holds a full CPU core), do not wait indefinitely or re-send it. If the last state is saved and committed, kill the Editor and relaunch with `-SkipBuild -Map <map>`; then time one iteration of the script before running it at scale. For transform-only Unreal Python actor edits, do not treat an empty dirty-map list as evidence that disk matches memory: the edits may not mark the map dirty. If necessary, force-save only the target world package with `unreal.EditorLoadingAndSavingUtils.save_packages([world.get_outermost()], False)`, then reload and compare the affected transforms. A successful tool response or screenshot alone does not prove the intended saved result. Choose evidence appropriate to the requirement: compilation and behavior tests, saved-state or map checks, reference checks, in-engine scenarios, visual inspection, or measurements with applicable conditions. Keep technical verification separate from creative acceptance: write a creative verdict into evidence only from the user's explicit verdict on that pass (otherwise `pending`), and mark any cause you did not measure as `likely (not tested)` rather than `because`.
