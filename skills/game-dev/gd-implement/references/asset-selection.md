# Environment asset selection

Use when environment implementation depends on vegetation, rocks or dressing not yet selected for the project.

1. **Define the visual role and viewing tier.** Read the controlling references and source brief. Identify required silhouette, season, ground attachment, intended traversal and close/panoramic sightlines; distinguish approved adaptation from source fact. Inspect the route and approved cameras before selecting detail: buds and contact detail belong where readable, while distant trees need convincing crowns and density. Keep existing evaluation guidance subordinate to the task's actual acceptance policy.
2. **Inspect installed content first.** Query AssetRegistry by class and relevant paths, then read candidate bounds and material references. Search plugin sample paths as well as `/Game`; filename keywords can miss useful assets. Render and inspect shortlisted native assets using the [thumbnail recipe](unreal-captures.md#native-asset-thumbnail-review). Trace source provenance before adapting a candidate: a smooth sample boulder with a generic ground material is not a scanned gravel asset. Reject a candidate once its visible shape or surface misses the role; procedural population cannot repair unsuitable canopy structure, stone shape or missing surface data.
3. **Check already-owned candidates before new acquisition or procedural substitution.** After resolving Editor ownership, read `FabToolset.FabToolset` with `describe_toolsets`. Prefer the signed-in Editor integration for account-library questions before broad public web searches: run targeted `FabToolset.SearchFabMyLibrary(keywords=...)` queries and page with `nextCursor`. Read `GetFabListingDetails(listingId)` for plausible candidates and inspect the first-party listing and images. Separate standing snags, detached logs and ground-scan patches: a title containing Dead or Fallen does not establish the requested role. Check listed dimensions and open/closed mesh type against the visible silhouette; small attached-floor scans are not whole fallen trees, and large-scale placement cannot repair that mismatch. Public results establish neither ownership nor current license entitlement. Refresh before evaluating reported library additions; authentication alone does not establish a current library result. `SearchFabMyLibrary` reads the live library on every call and needs no Fab window: page it with `sortBy='newest'` until `nextCursor` is empty. Reconcile returned counts and unique IDs, then compare IDs with the prior snapshot; presence does not establish when the user acquired an asset. Search by name/exact ID when native summaries omit seller/type metadata. Treat cached zero matches as inconclusive, not a reason to reacquire. For authorized owned Quixel glTF intake, call `FabToolset.InstallFabListing` with the listing's `gltf` install option; a `choose-file` reply lists the quality tiers as `files`, so repeat with the chosen `fileId`, then confirm the assets on disk from later calls. If native My Library works but automation disagrees, inspect the actual bridge error before requesting another sign-in; use native Add to Project as a bounded fallback, not proof that automation is repaired. For an authorized repair, test live credentials and individual-listing coverage separately because the UE-pack feed can omit source listings. Prove a genuinely absent quality imports, then same-quality idempotence and different-quality selection; an existing result alone is not end-to-end intake proof. Verify exact listing IDs, registered assets and saved/reloaded texture/material references, including shared importer dependencies in the package delta. Keep native/EOS account identity aligned and never export credentials. For free candidates, query `FabToolset.SearchFabListings` with `bFreeOnly=True` and short role terms (debris pack, branch, stump, log, mossy rocks, dry grass). Read each result's `assetFormats`: a texture-only listing is a 2D atlas, not a mesh. Download the results' `thumbnailUrl` images into one numbered contact sheet, judge the role fit yourself, then present the sheet with a table and ask for the user's explicit licence acceptance before any free install. Start one install per Editor call and confirm it landed before the next. Treat “From Free” as unverified until the exact selected tier grants downloadable source: UEFN Reference-Only is not source access for a standalone Unreal project, even when the listing also advertises FBX/glTF. Do not request license acceptance or recommend adding a reference-only offer to the library as a source-access workaround. If access is gated, resolve the specific access decision rather than spending repeated searches on unrelated catalog listings. Retain only relevant pack/version/provenance evidence, not account identifiers or a complete library dump.
4. **Separate entitlement, compatibility and fit.** Ownership does not mean project adoption, an engine-version listing is not a tested ingestion result, and a leafy hero image does not establish a usable leafless variant. Where experimental authoring is advertised, distinguish that from the proposed runtime representation. Treat conversion/export as unverified until exercised; an exposed export setting alone does not prove a working path.
5. **Request only the reserved decision.** If intake approval is required, recommend the smallest bounded evaluation and name the exact packs, whether they are already owned, and the unresolved visual/runtime questions. Keep purchase, license acceptance, experimental project settings and production adoption outside that approval unless explicitly included. Continue independent authorized work where useful; do not create speculative replacement meshes merely to avoid the decision.
6. **After approval, prove the result in context.** Import through the supported Editor interface, verify actual asset paths, adapt only task-owned assets, and inspect representative local and regional views. If the supported downloader installs an entire pack but approval is component-only, stage it in a disposable project, wait for the terminal `imported` state rather than download percent alone, and select packages through the Editor registry. Check destination collisions and the selected packages' `/Game/` dependency closure before calling `AssetTools.migrate_packages(selected, destination_content, options)` with `MigrationOptions.prompt=False`, `ignore_dependencies=False`, and `asset_conflict=AssetMigrationConflict.SKIP`; preserving vendor paths avoids broken references. Do not install the whole vendor scene into production or parse/copy opaque packages manually. Serialize Editor control and verify the reconnected project after each switch. Match material-relevant rendering prerequisites in disposable intake projects before evaluating Nanite assets: a bare project can default to SM5 even when the host uses SM6. Verify the restarted staging log's actual feature level and shader platform; do not alter the correctly configured host to fix a staging warning. Load the exact migrated assets in the destination project and compare its package delta against the approved shortlist, because a successful migration request alone does not prove selective intake. After native import, inspect dirty packages and save only the authorized imported family before reloading; `imported` can precede final material saves. Check both values from `reload_packages`: a true boolean with explanatory text can mean dirty packages were skipped. Inspect actual material parameter references rather than expecting one override per imported texture; an auxiliary fuzz map can exist without an explicit override. For texture resolution, read `blueprint_get_built_texture_size()` after build/export or actual native export dimensions: immediate streaming size getters may report only a 32px resident mip for a 4K source. Enable and save spline-mesh material usage before road PIE trials; a compiling ordinary-plane preview does not prove spline rendering. Record selected paths, placement method and ownership; save/reload and verify instances/references. Keep technical verification separate from the creative owner's acceptance.

When parked for a decision, record the exact pending approval and the verified saved/dirty handoff state in the existing task, release Editor ownership, and reconcile it again on resume. Do not record a failed or untested ingestion/export attempt as a reusable recipe. For authorized pruning of unused intake/trial packages, use [native package pruning](../../gd-code-review/references/evidence-publication.md#native-unreal-package-pruning), not a second cleanup procedure here.

## Close-surface asset fit

Use for realistic road, soil, rock and forest-floor treatment at player/cinematic distance.

1. Map each visible job to an ingredient before import: compacted fines/gravel surface, selectively exposed rock geometry, organic edge litter/wood/roots, and the underlying landform. Shortlist the smallest complementary asset set, not a whole vendor scene or a new biome.
2. Inspect local archive directory listings before importing, then preview relevant loose base-color maps at useful resolution; a contact-sheet impression can hide contour-like rock patterns unsuitable for gravel. Do not parse opaque Unreal packages outside the Editor. For owned environment packs, a metadata-only manifest can reveal useful road/soil/height texture families hidden behind a village-themed title; filenames identify candidates, not visual fit or channel packing. A source package's older listed engine version requires a bounded forward-load check, not automatic rejection or project upgrade. Inspect actual maps and meshes, not only pack beauty shots. Prefer coordinated base color, normal, roughness and height data for the surface; inspect stone silhouette, fractured/weathered variation, physical scale and soil contact. Scanned provenance is useful, not proof of fit. Avoid a uniformly crushed-gravel or smooth-pebble vocabulary when the reference mixes hard earth with varied partly buried rock.
3. Before the trial, read the listing's physical scan area and use that tile size; do not enlarge a small scan to make its details artificially readable. Prove one small patch in both a representative close view and the intended road-eye/cinematic view under unchanged lighting before broad placement. Record which visible cue the ingredient must improve at each distance; recognizable individual debris close up does not establish a readable organic floor from the road. Inspect leaf shape variety, soil openings, overlap, surface response and ground contact rather than choosing from a filename or brown tint. Use a [PIE-only dressing trial](unreal-captures.md#pie-comparison-cameras) when existing assets and instancers suffice. Reject an ingredient that remains pale slivers or visibly repeated shapes at the target view instead of multiplying copies. For scan-derived physical litter, retain native scan scale/UVs and validate cutout previews before mesh creation; request polygon coordinates in a dedicated labeled crop's own pixel space, then convert them programmatically, because full-image/crop coordinate descriptions can conflict. Isolate the added geometry with a matched visibility toggle: inherited normal-map litter can be mistaken for a successful geometry pass. A macro proving rendered blades does not establish a road-eye improvement, and native grounding does not clear angular or propped-card appearance. Organize compacted fines, coarse aggregate and organic accumulation at distinct scales; count growth is not a substitute for that hierarchy. Diagnose exposure and material response before repeatedly lowering color values. Keep fine relief in shading and silhouette-bearing detail in geometry as appropriate; do not require displacement everywhere to acknowledge real improvement.
4. Evaluate both shoulders as a physical/material transition. Brown shading alone does not establish leaf litter, exposed roots or irregular banks. Use irregular organic accumulation and ground contact where visible; obtain the bounded paint/terrain authorization when the protected forest floor or grade prevents the reference transition.
5. If the representative view still fails, distinguish unsuitable ingredients from missing application scale before extending the treatment. For forest floors, large banks and isolated leaf meshes do not test the intermediate shape of litter mats, shallow hollows and root/stone transitions. If that hypothesis is authorized, retain the same texture and lighting on a small duplicated evaluation surface and vary only deliberate supporting relief; treat the result as untested until compared at player height. Keep native spline editability and existing scene controls; decide whether dressing must regenerate with road edits before choosing fixed world-space placement. Report an explicitly accepted static-dressing ceiling rather than presenting it as road-responsive generation.

   When considering parallax occlusion mapping, inspect the actual imported texture channels and owned source files for a matching height map before graph work; ORM or grayscale albedo is not verified height. Reuse the installed engine material function after discovering its inputs. Separate real silhouette/collision relief from shader-only apparent depth: compare shape-only first, then add POM as a distinct variable if useful. Check moving and grazing-angle artifacts, distance fallback and representative cost before selecting it; function availability or a still image does not prove scene suitability.

## Preservation-first PCG migration

For an accepted baked woodland, reuse native PCG sampling, instancing and Actor spawning rather than replacing the accepted tree assets or reshuffling the whole stand. Retain fixed art-directed candidate transforms in the graph, re-ground/filter them against current terrain, native spline corridors and tagged actor footprints, and use fixed-seed surface samples to infill abandoned road corridors. Make scene-reading elements non-cacheable for explicit Generate, verify input requery, and expose practical margin/slope controls. Keep runtime generation separate from Editor authoring scope. For needle-bearing skeletal assemblies, test native skinned instancing before scaling per-tree Actor spawning; follow the assembled-vegetation comparison recipe below. Verify actual PIE crowns and serialized component flags rather than accepting a broken static fallback. Preserve old actors/foliage as disabled recovery without double rendering. Test moved roads, tagged clearings, changed terrain, repeat generation and restored baselines across separate ticks; save, fresh-launch and inspect Editor/PIE results. State the managed footprint, candidate-based layout ceiling, axis-aligned footprint and canopy-clearance limits. A portable saved-state checker must not depend on ignored recovery files. When extending a stand, partition preservation by retained candidate roots plus documented road-infill roots, not its bounding rectangle: sampled additions can land inside that rectangle outside the candidate footprint. Keep per-candidate GroundOffset identity in independent contact checks; one offset per mesh loses varying stone penetration. Trace tagged detail-ground support as well as Landscape. Read native material pin names before wiring: TextureSample can export `Coordinates` while MaterialEditingLibrary expects `UVs`.

## Incremental density revisions

Use for additive trees or undergrowth within an existing treatment, not a larger regional forest footprint. For a visual consistency correction without a requested percentage, first compare matched route views and local species/form counts with the accepted sample. Label fixed-radius counts as local samples, not an area-normalized census; identify the missing vegetation tier before choosing additions, so sparse undergrowth does not trigger an unrelated tree-density increase.

1. **Freeze the current visible population.** Read the latest saved snapshot and verify live generated counts before calculating additions; PCG candidate counts include excluded seeds, and hidden recovery is not active density. Resolve the denominator separately from the addition species. For a total-tree increase, compute `added = math.floor((oak + pine) * fraction + .5)`; if all additions are Pines, add that entire delta to Pines and preserve Oaks. For a Pine-only percentage, use the Pine count as denominator. Preserve species balance only when that is the requested outcome. Report rounded additions, final per-species totals and actual overall percentage; keep the footprint fixed and exclude stones/undergrowth from the tree denominator.
2. **Reuse accepted forms and placement controls.** Sample existing species/forms and their height/breadth mix; preserve mixed upright/leaning directions, low crowns and mature anchors. For additive feedback, append trees without moving, resizing or replacing earlier placements. Keep terrain, bramble/stone and regional exclusions protected unless explicitly included.
3. **Plan the complete delta before mutation.** Use deterministic candidates within the existing footprint, test root spacing against old and newly planned roots, and check transformed geometry against the road/drainage. Resample a different existing anchor after bounded local rejections so one crowded pocket cannot exhaust the whole plan. Prefer full transformed bounds when they satisfy the request; use the established low-geometry/overhead-clearance method only where full-crown exclusion would defeat required shoulder infill. For winding native spline roads, measure clearance against the generated curve and widths, not straight chords between control points: chords can cut across bends and falsely report an intrusion. Evaluate native Hermite positions and interpolated scales, form sufficiently fine adjacent spans, and subtract the maximum span half-width plus the transformed vegetation envelope from point-to-span distance; compare the remaining margin with the existing requirement. Retain world transforms and the mesh-axis/width convention from the actual components. Derive contact height from the actual terrain. Dry-run the exact count and unique labels/roots before applying.
4. **Append through the current authoritative representation.** For baked foliage, reuse existing types and proven actor setup. For PCG, retain the candidate-array prefix and append copies of existing species candidates with new transforms; preserve asset/output-pin pairing, grounding offsets and native spawner settings. Guard the expected starting array length before mutation so an ambiguous result cannot double the additions. Generate once, then inspect output in a separate call: candidate count alone does not prove the requested visible delta survived terrain/clearance filters. Reconcile rejected candidates by stable identity against the authoring plan and the actual footprint, slope and clearance rules before accepting a count difference. If an exact output count was requested, supply the remaining valid placements within scope; otherwise report planned, generated and filtered counts separately. Preserve the existing filter thresholds rather than lowering them to fit the plan. Journal the applied delta and update the single current snapshot only from verified output.
5. **Verify the delta and preservation separately.** Partition generated output into prior placements and additions using stable IDs or verified unique asset/XY keys, assert prior transform/asset hash equality, and assert the exact added count and species. Match the original candidate prefix independently. Keep this preservation check runnable from repository inputs: the graph's original prefix plus a recorded prior-output hash can avoid another full placement ledger; verify key uniqueness rather than silently collapsing instances. Test every added root against Landscape collision and check clearance/spacing against both old and new roots. Repeat Generate, save/reload the graph and map, then verify Editor and PIE counts and hidden recovery. Hash protected packages to isolate graph/map changes from terrain, road, vendor and configuration work. Measure consequential cumulative cost with the same camera and effective settings, preferably in the same Editor process; retain unresolved render-fraction limits instead of claiming a production performance pass.
6. **Show the visible result, not just the arithmetic.** Refresh matched road and oblique comparisons plus the existing current views/panorama. Report subtle infill honestly: more tree count does not imply the same percentage of screen opacity, and a requested increment need not erase every natural gap. Preserve the previous verdict as baseline provenance; obtain the current verdict without promoting it to full-region or production acceptance. Keep raw plans/recovery local and reuse the maintained verifier.

## Selective upper-height revisions

When the user wants a higher tree-size ceiling without making every tree taller, measure the current live population by mesh bounds and per-instance Z scale. Select a deterministic scattered minority of mature forms, retain young trees and the majority, and leave roots, rotations, assets and other species fixed. Widen the upper tail rather than uniformly scaling the population; grow breadth moderately with height and verify full transformed crown/lean clearance before editing existing PCG candidate scales. Write modified array structs back, then compare selected versus unselected output, repeat Generate, save/reload and inspect canopy and road-eye-height views in Editor/PIE. Report maximum and median separately, labeling bounds×scale as upright-equivalent asset height rather than botanical data. Keep the portable checker on the prior shared placement baseline plus selected indices; preserve exact numerical edge cases when reconstructing a hashed baseline rather than weakening drift checks. Earlier density/cost results become baseline evidence when scale changes; do not present them as a new performance result.

## Assembled vegetation and seasonal variants

Use for native Nanite vegetation assemblies or seasonal changes to owned tree packs. Discover live signatures before calling the APIs below.

1. **Reconcile the imported inventory.** Query AssetRegistry by exact vendor subfolder after Fab import; returned paths can include previously imported packs under a shared install root. Count the deduplicated package union, not the sum of shared-root reports. Keep provenance and selected paths with the project, not account data.
2. **Inspect the complete native tree.** Read `nanite_settings` → `nanite_assembly_data` through chained `get_editor_property` calls; inspect part paths, local placements and material remaps. Skeletal source geometry or render fallback can omit assembled branches/needles, so a trunk-only preview is not proof of a bare seasonal tree. After an authorized runtime-feature change, verify persisted config and the live value on a fresh launch; capture the native assembly before attempting conventional conversion. Verify independent assets against the current feature state rather than hard-coding an earlier off-state.
3. **Reuse structure before generating more.** Compare existing variants, then combine modest rotation/size changes with genuinely different crown/branch forms. Preserve the requested mature canopy mass while adding low screening: replacing all near-road pines with small forms can lower foliage yet remove the tall, full evergreen presence. Inspect height, crown volume and eye-level screening separately in matched road views. Distinguish a low bark-nub attachment from the lowest substantial needle-bearing branch: shortening below the former can leave the live crown high. Preserve branch junctions with a continuous stem warp plus matching crown-node/embedded-branch translation, and inspect actual needle mass rather than asserting branch-origin height equals screening. Include the user's pictured specimen; random placement selection can miss the very tree they pointed out. Check actual rotated crown bounds before saving enlarged trees; source width alone can miss leaning or off-center crowns. For sparse roadside infill, distinguish physical root/low-limb/needle clearance from harmless overhead crown overhang: a full-crown radial exclusion can force every trunk away and preserve barren bands. Reuse measured lower-geometry envelopes including assembly parts, verify conservative upper-crown road height, and inspect matched roadside views; do not relax road/drainage clearance to fill a picture. For size feedback, sample height and breadth separately across a visibly broad age mix while preserving mature roadside anchors. Reuse the sampler for current resizing and later additions; keep the closest constrained roots unchanged and check actual rotated crown bounds before saving. This varies thickness/crown breadth, not branch structure. For percentage feedback, follow [incremental density revisions](#incremental-density-revisions); preserve the accepted visual vocabulary rather than treating more placements as new structural variety. For overly upright woodland, mix bounded lean in varied directions with genuinely curved whole-mesh forms; do not claim tilting a straight trunk makes it crooked. Keep roots fixed and test leaned crown bounds. Preserve authoritative foliage instance data: a component-only transform edit can leave FoliageInfo unchanged. Inspect the current values of `TypedElements.EnableSMInstanceElements` and `TypedElements.EnableFoliageInstanceElements` before acquiring foliage script handles. Change gates only inside the owned authoring session and restore their previous values afterward. Prove a native replacement with handle acquisition, interface lookup and a transform query before removing an existing bridge; use reads rather than a no-op setter, which can dirty the package. If that path cannot supply authoritative writes in the current engine, retain or build the smallest guarded C++ bridge to the native instance manager, with expected-old-transform validation and no component-only fallback. Exercise null/index/stale-transform/invalid-scale rejection and non-Editor-world rejection alongside a valid edit; require a real build, FoliageInfo readback, save/reload and PIE. Treat the probe result as version/session evidence, not a permanent claim that the native API is unavailable.

   Treat an accepted sample set as a visual vocabulary, not a population cap or a requirement for a unique mesh per tree. Add geometry variants where route/cinematic views expose repeated silhouettes; omit unreadable bud-level detail from distant representations. Closed buds are actual small geometry at verified twig contacts, not simply shrunken mature leaves. Record botanical claims separately from the accepted artistic interpretation.

4. **Change leaves in task-owned parts.** Use verified material remaps to remove leaf geometry while preserving wood, then confirm the native assembled output is visibly leafless. Top-level component overrides can read back while nested foliage remains visible, so slot equality alone cannot establish seasonal correctness. Validate all retained geometry and disclose omitted parts; a saved candidate does not complete an unverified source family.
5. **Choose the smallest suitable representation.** Estimate expanded geometry before flattening: sum each part's source triangle count multiplied by its placement count. Source, fallback and assembled totals are different measurements. Reuse shared assembly parts when possible. Preserve proven local transforms; strip skeletal attachments only after rejecting bone-relative transforms. Construct `unreal.Transform` rotation with `unreal.Quat(...).rotator()`. If a bounded crown candidate needs continuous reshaping, append verified parts at their transforms, use `GeometryScript_MeshQueries.get_all_vertex_positions` and `GeometryScript_MeshEdits.set_all_mesh_vertex_positions` for a smooth crown-only warp with the lower trunk unchanged, then recompute normals. Moving part origins alone separates branch junctions. For thicker/lower Oak forms, reuse merged wood and deform the entire surface continuously: thicken the stem with a crown-fading radial warp, compress the lower stem with a rooted monotone Z mapping and translate the upper crown intact. Inspect actual low branching in source-height slices and in placed eye-height views; do not confuse a lower branch-origin number with visible substantial limbs. Measure the merged result and clear saved assembly data so it does not render both merged and instanced geometry; mass-placement suitability still requires scene evidence.
6. **Verify saved output, not requested flags.** Inspect UV validity, triangle counts, material paths, Nanite flags and assembly nodes. If a generated save reads back Nanite disabled, reconcile the existing task-owned mesh with the discovered `StaticMeshEditorSubsystem.get_nanite_settings` / `set_nanite_settings` methods, save and reload; replaying creation risks duplicate or conflicting output. Keep current counts separate from source assembly metadata after conversion.
7. **Compare converted and native representation before population.** Apply the main skill's RAM-headroom workflow; regional regeneration can temporarily retain old and new actor populations, and skinning-buffer capacity warnings are a separate correctness signal. On UE 5.8, test native `InstancedSkinnedMeshComponent` / `PCGSkinnedMeshSpawnerSettings` before flattening skeletal Nanite tree assemblies: a reference-pose instanced path can retain needles while avoiding per-tree actor overhead. Prove a small native-vs-instanced render before modifying the existing graph; retain old spawners disabled, set reference-pose rendering/no collision explicitly, then clean up managed old output, save/restart and Generate to avoid population overlap. Verify persisted counts/transforms and actual PIE needles. Bulk-created skinned instances can have invalid `get_instance_id` lookups; read serialized `instance_data` Transform3f fields and compose with component world transform for read-only preservation checks, using explicit float tolerances. A static conversion can preserve every Nanite assembly node/material record yet omit Pine needles in the render. Matching a root voxel setting is not a proven repair. Inspect warmed source/converted views; reuse the native needle-bearing tree when suitable and measure that actual representation. For generated skeletal assemblies, check actual render sections as well as material slots: a trunk-only base can retain foliage remaps but hide the needles. Embedding one real source branch in the base and removing that exact assembly node restored crown-wide needles in a verified candidate; preserve UVs/material remaps and confirm save/reload plus PIE. Do not add dummy triangles or infer complete foliage from metadata. For skeletal actors, persisted Editor tick-start flags can still be overridden by PIE activation; verify animation, tick and collision separately after reload and in PIE rather than claiming tickless runtime from Editor readback.
8. **Present a matched comparison.** Use the [native comparison workflow](unreal-captures.md#native-comparison-when-a-capture-looks-wrong), keep camera/scale consistent and show a separate close detail crop. If one-shot SceneCapture fragments disagree with warmed native views, use the latter as labeled appearance evidence without claiming the other render path is fixed. Read camera and selection immediately before/after capture; reconcile unexpected external control before restoring over it. Deliver the reviewed set with explicit wind/collision, missing-part and scene-cost limits, then remove task transients and verify restored Editor state.

## Nanite assemblies and PVE pitfalls

- A leaf-material override can read back on a Nanite assembly component while nested leaves still render; compare native captures, and author a leafless assembly instead of trusting slot readback.
- One-shot SceneCaptures of Nanite assemblies can show fragments a warmed viewport doesn't; inspect the native view before changing geometry.
- Moving assembly-part origins splits branch junctions; reshape a crown with one continuous crown-only deformation over merged wood parts, trunk unchanged.
- To shorten a bare lower stem, find the lowest needle-bearing branch (not the lowest attachment nub), compress the trunk below it and translate every retained attachment together; never shrink or bury the tree.
- Radial crown clearance leaves barren roadside bands; clear roots and low wood/needle envelopes against the real road and allow overhead canopy only after checking its height.
- Preservation checks must partition by retained root identity, not by bounding-box membership; additions can share the accepted stand's rectangle.
- PVE Export nodes only pass data through; meshes are written by the PVE editor's Export button, so a PCG-run PVE graph exports nothing. Duplicate the PVE asset and retarget every Export folder first (defaults point at the vendor folder with Replace).
- A PVE Carve before a Mesh Builder shrinks the kept trunk to twig radius. For a trunk foot, `plane_cut` the exported SkeletalMesh via `ModelingService` instead.
- PVE Export opens a modal dialog that freezes the game thread, so every MCP call hangs until a human closes it. Script the setup, then ask the user to press Export; check `gameThreadStallSeconds` in the health file rather than retrying.
- Kit terrain tiles (e.g. flat-based peak tiles) must have their base sunk below the lowest ground in their footprint, or the base shows as a flat apron.

## Volumetric clouds

- Engine cloud material instances give a fair-weather sky by parameters alone and reuse compiled shaders (a custom-material recompile has crashed UE 5.8), but cannot place summit-sized clouds: the global mask is applied after the height profile, so masked cloud renders as flat-sided boxes. Localized caps need a custom cloud material.
- Horizontal layout wind slides the whole pattern across the world; keep only its vertical component when clouds must stay anchored to terrain.
