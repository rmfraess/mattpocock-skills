# Unreal reference-comparison captures

Use when a map or environment must match an approved camera view, especially when the Editor is backgrounded or the UI viewport has a different aspect ratio.

## Reference-framing workflow

1. Read the target image's aspect and composition. Capture a baseline from the saved camera's **actual transform and horizontal FOV** at matching output width/height. Do not treat an Editor viewport screenshot as a fixed-camera panorama: its pixels follow the UI viewport ratio even if `CameraComponent.aspect_ratio` is set.
2. In VibeUE, use `unreal.ViewportService.capture_scene(camera.get_actor_location(), camera.get_actor_rotation(), width, height, output_png, 0, camera.camera_component.get_editor_property('field_of_view'), ev100)` for a perspective PNG independent of viewport frames. Discover the live result fields: the Python `SceneCaptureResult` exposes `success`, not the C++-style `b_success`. Retain the response and inspect the actual output before retrying after a result-parsing error, because rendering may already have completed. Set a fixed manual EV100 if background auto-exposure is dark; inspect the rendered pixels before accepting the result, not just the success flag.
3. Preview candidate poses with `capture_scene` before moving the saved camera. Make one reversible, unsaved layout batch, then inspect the approved aspect and an overhead diagnostic together: moving a flank biome outward can push it off-frame or high onto the horizon, while moving the camera back can shrink the settlement and bring southern scenery into the foreground. Check world-space adjacency and road/building clearance as well as screen position; reject a worse trial by reloading the saved map only after confirming all unsaved changes belong to the trial, rather than piling on compensating markers. For the overhead image use an orthographic capture (`ortho_width > 0`, pitch -90) at a height appropriate to the scene; an overly distant camera can yield an all-black file despite a successful call. Choose yaw from the project's north axis: with +X north and +Y east, yaw 0 makes north screen-up and east screen-right; a generic yaw -90 example rotates that map. Inspect pixels and adjust height/coverage before accepting the diagnostic.
4. When implementation includes task-owned saves, save the target map, reload it, read back the intended transforms/references and dirty state, then recapture at the identical panoramic pose. A good unsaved frame does not prove the persisted world reproduces it. For read-only or package-preservation diagnostics, keep the saved map unchanged instead. Keep creative acceptance separate from technical capture/readback.
5. When thin or occluded proxy roads need a route-identity diagnostic, capture a closer north-up orthographic view of the **saved** map. Read the route actors' centers, yaw, scale and mesh local half-length (50 cm for the engine's basic cube); project actual segment endpoints, then check adjacent joins and the village junction numerically. For yaw 0 with +X north/+Y east, map world `(X,Y)` to image `(px,py)` as `px = W/2 + (Y-Y0)*W/ortho_width`, `py = H/2 - (X-X0)*W/ortho_width`; confirm the projection against a visible landmark. Overlay labeled centerlines on the real capture, inspect the result and unannotated panorama, and say explicitly that the colors are **annotations, not roadbeds**. An SVG overlay rasterized by a browser is enough for simple callouts; do not add a project dependency just to label an image. Record camera, axes and the connected-core proxy envelope separately from scenic backdrop and production bounds. Publish evidence only within authorized publication scope, verify the remote files, and leave any still-obscured route in the panorama as a visibility question for creative review rather than claiming the overlay repaired it.

## Representative-treatment acceptance

1. Read the ticket's own acceptance criteria and the parent/wider-region split before choosing views. Inspect the approved reference images as targets, separately from actual engine captures; an image-analysis recommendation to accept the reference is not acceptance of the implementation. For a finished close-road treatment, load retained ground/road references as well as regional panoramas before selecting materials: a panorama cannot establish granular soil, embedded-rock relief or verge fidelity. Treat flat procedural stone flecks as a provisional cue, not realistic embedded stone merely because shader/collision checks pass.
2. Capture the current saved scene at the established panorama transform, horizontal FOV, output aspect and exposure. Keep the unannotated full-resolution image. If the treatment is tiny at that scale, project authentic saved placement coordinates for an optional scope callout and label whether it marks roots, a route or canopy; an enlarged box or crop must not imply completed regional coverage. Use close views for needles, buds and junctions that the panorama cannot resolve.
3. Add only the complementary road, medium and immediate-shoulder/close views required by the pass. Resolve the current route before reusing an old eye-level camera: winding edits can leave its XY off the road. Prefer current spline geometry; if needed, use a bounded cross-road collision scan against the intended route's components, select the current ribbon center, and place the camera at the measured surface plus the stated eye height. Record the resulting camera, warm the native view, and inspect it. Distinguish coarse angular bramble/stone or a hard road edge from demonstrated fragmentation, floating, missing materials or blockage. Report a snow-like reading as appearance feedback, not proof of snow intent or permission to repaint accepted ground. If image analysis proposes fallback or missing materials, reconcile the visible pattern with live component assignments, material diagnostics and the accepted baseline before changing content; pale soil alone is not a fault diagnosis. Give image inspection the intended surface and relevant verified facts, then ask for defects without steering it toward approval.
4. Re-run the applicable saved-scene checks and verify package preservation for an evidence-only pass. Reuse clearly labeled scene-cost evidence when its relevant inputs remain unchanged; new captures alone do not require another benchmark. Update the existing report/snapshot and deliver one compact local review plus the panorama. State which coarse limitations need the creative owner's verdict and which wider-area work belongs elsewhere; technical success supports only its criterion, not visual approval or closure.

## PIE comparison cameras

Use a transient runtime camera when comparing a saved environment without changing its persistent camera actors.

1. Prepare terrain/contact queries and saved-scene checks outside PIE; Editor-world setup helpers can resolve no Editor world while PIE is active. Save/reload before starting the runtime comparison.
2. After PIE readiness, discover `PIEActorService.spawn_actor` and spawn `/Script/Engine.CameraActor` into the intended world role with a task-specific transient label. Keep only its JSON handle/path between calls. Do not reuse a camera-finding helper until its expected actor is confirmed in this new PIE session; a prior session's transient camera no longer exists.
3. Inside a function, fetch the live game world, find that camera, set its transform/FOV and call the local player's `set_view_target_with_blend(camera, 0)`. Return only primitive camera readback. Let native frames settle, capture with `source="game"`, and inspect the image. Function-local UObject references must not escape into persistent Python globals. Return from any function retaining a World/package before loading another level in a separate call; a local World still held on the stack can trigger `World Memory Leaks` during same-function reload. When references are uncertain, save task-owned state and use a graceful fresh launch for persistence verification.
4. For material auditions, override only the intended components resolved from the PIE world, read back assignments, and record the affected paths; stopping PIE discards those component overrides without saving the map. Prepare and save any authorized material usage flags outside PIE: a valid ordinary-plane material can render fallback on spline meshes, and Editor asset saves may be refused while PIE runs. After production integration, repeat the saved/reloaded comparison with no runtime material override so the audition is not mistaken for persisted behavior.

   For an existing-mesh dressing trial, prepare deterministic transforms against actual road/bank/Landscape collision before PIE, and finish writing every harness input before starting its dependent runtime call. Capture baseline road-eye and detail views with the transient camera. In a function, resolve the PIE world's existing owner/component; assert its expected mesh, material, collision role and starting instance count. Append only the trial transforms with `component.add_instances(transforms, True, True, False)` for world-space placement without navigation updates. Verify returned indices, final count, unchanged prior transforms and added-transform readback; then return to native frames before capturing the same two views. Keep shared mesh/material assets unchanged: PIE isolation protects world instances, not edits to referenced assets. Label captures as temporary PIE trials, not saved results. Treat a traced instance origin as grounding evidence only; curled tips or an uneven mesh still need low-angle contact inspection if full surface contact is claimed.
5. Destroy the exact registered camera handle, request StopPIE, and confirm it has stopped in a later call before Editor-world queries. Verify the Editor component's original count/transforms, dirty-package parity and protected package hashes; the PIE append is discarded rather than manually removed from the production component. Restore the original viewport/session controls. No persistent camera, gameplay controller asset or map change is needed for this harness. Adopt only a visually useful trial within production authorization, then perform separate saved/reloaded and runtime checks.

## Native asset thumbnail review

Use this before placing an unfamiliar installed mesh when a small preview can reject the wrong silhouette or seasonal state without changing the map.

1. Discover the narrow `EditorToolset.EditorAppToolset.CaptureAssetImage` schema and call it in Editor Python with `vibeue.exec_tool('EditorToolset.EditorAppToolset', 'CaptureAssetImage', {'assetPath': path})`. Retain the result object instead of immediately treating it as a dictionary: native thumbnail rendering can return a pending async result even through the helper.
2. If the result is asynchronous, return to the agent and check `result.is_complete` and `result.error` in a later Editor call. On completion, parse `json.loads(result.value)`; for an already-decoded result, use it directly. Read the image payload from `decoded.get('returnValue', decoded)` and write `base64.b64decode(image['data'])` to a task evidence file with the matching format. Print the file path, not the base64 payload, to keep tool output small.
3. Actually inspect the image. Use it to assess gross branching, foliage, proportions and surface treatment, not to certify fine detail, seasonal controls, scene integration or performance. A thumbnail can reject an unsuitable asset; acceptance requires representative in-scene views.
4. Check dirty lists afterward and preserve unrelated packages. Keep the original asynchronous handle through a caller-side parsing error and read its completed result rather than requesting another render; the operation may already have succeeded.

## Material-pass evidence

1. Map every required surface distinction to an existing layer/instance and a representative view before editing. A broad seasonal recolor can satisfy “brown ground” while still missing a requested stone-versus-earth cue; check each named distinction rather than treating a pleasant panorama as complete coverage. For a surrounding-ground contrast change, inspect the installed texture itself before assignment, duplicate a shared ground material only into the authorized evaluation scope, and export its graph. If the existing final blend is `Lerp(background, road, RoadSoil)`, replace only the background input with the suitable installed texture and minimal tint, reusing existing world-XY coordinates. Preserve the road branch, mask, roughness and paint; the feathered transition may intentionally change color even though the road branch is untouched. Do not add normal/ORM stacks, physical litter, repainting or forest regeneration merely to make the route legible. Compile with `MaterialEditingLibrary.recompile_material`, assert an empty error list, check referenced textures with `MaterialNodeService.get_material_diagnostics`, then save/reload the material and map before reviewing. Compare decoded paint, height and actual placement baselines unchanged; update only authorized package fingerprints in the existing evidence after those semantic checks pass.
2. Compile changed material structure, then let dependent Landscape shaders and streaming settle. Apply this capture gate after weight imports and map reopens too: unchanged material structure can still need Landscape weight permutations. Discard warm-up images. If offscreen captures retain a hard fallback checkerboard, use the native realtime viewport warm-up below, recapture at the same pose, and rebuild every comparison sheet from the settled originals. If the fallback persists, inspect compile errors/dependencies rather than adding compensating nodes. Compare matched pre-change/current crops before classifying fine low-contrast repetition as a newly introduced checkerboard; conflicting image descriptions require evidence reconciliation, not another material edit. If an eye-level view looks unchanged or image analysis says a texture is absent, inspect a matched overhead plus an original-resolution boundary crop and compare the same sunlit background/feature regions before touching the shader again. A grazing camera can fill the frame with the unchanged road, and downscaling/shadows can hide moderate background contrast. Read back native material inputs and texture references to distinguish a genuinely missing assignment from poor framing; neither compile success nor a negative image description establishes visible correctness alone. Label mismatched guides, exposure or viewport mode as comparison confounds.
3. Capture the actual edited boundary from a local top view and a useful oblique view, alongside the fixed panorama. Place the camera using the painted mask/route coordinates and trace its ground height; a grazing camera inside a broad patch may look uniformly brown or show distant mountain stone instead of the local transition being tested. Describe a flat gray paint patch as a coarse stone-color cue, not demonstrated rock relief or scanned material realism.
4. Deliver a small labeled before/after comparison and a compact ground-view sheet using the available image tooling. Preserve full-resolution originals and exact poses as evidence; the sheet helps the user judge the work without searching through files. For subtle infill, add a relevant full-resolution detail crop if the overview reduction hides the change; label an imperceptible or restrained result honestly rather than presenting instance-count growth as visible improvement. Keep persistence claims tied to cold readback and output checks, not a saved/cold image label. Match exposure as well as pose/FOV for causal color comparisons; disclose auto-exposure differences when a sheet supports only qualitative review. Fixed manual EV does not guarantee pixel-stable SceneCapture output: compare an unchanged control view before attributing image differences to material edits, and use exact source/package readback rather than image equality for preservation when streaming or rendering varies. Refresh captures and semantic reports after corrective edits so the reviewed pictures and persisted asset state agree.
5. When the material change warrants scene-cost measurement, record the effective viewport dimensions, render percentage, camera, quality settings, hardware and Editor/PIE/standalone mode **before** sampling; monitor resolution is not viewport resolution. Determine CPU/GPU binding first, collect warmed samples on separate ticks with session throttling disabled, and restore the original controls afterward. Confirm ticks represent new rendered frames: read `unreal.SystemLibrary.get_frame_count()` and deduplicate that native frame counter; `PerformanceService.frame_timing()` does not supply a `frame_counter` field. Cancel a failing callback before correcting it, discard its partial sample, and unregister on errors. Keep screenshots, asset queries, saves/reloads and other game-thread-blocking tool work outside the timed sample; readback stalls can dominate a short observation. Repeated stale frame/GPU times in Slate callbacks are not representative samples. Mark unresolved automatic render fraction and invalid timing explicitly rather than claiming a benchmark. An after-only Editor sample measures the resulting scene, not incremental shader cost or runtime performance; claim a delta only from matched before/after workloads. Record a crash/relaunch or process change between states as a confound even when camera/cvars match; separate-process parked observations do not isolate the change's cost. Apply only an approved target, not a tool's default frame-rate gate.

   For a material's incremental PIE cost, A/B inside one PIE session where possible, or in consecutive sessions at the same placed camera: swap the new node's code to its pass-through, stop and restart PIE (material graph edits need PIE stopped), take at least two `frame_timing()` readings in **separate** calls ~8 s apart, then restore the code and verify it against the saved copy before saving. `time.sleep` inside one Editor call blocks the game thread, so repeated readings in that call return the same stale frame.

### Bounded PIE cost and loading observations

Use when current loading/cost evidence is missing from a foundation review; this is not an optimization pass.

1. Read `PlayerController.get_viewport_size()` for the actual timing viewport and record capture output dimensions separately; the screenshot tool can resize its image. If automatic resolution obscures comparability, snapshot and temporarily set `r.Editor.Viewport.OverridePIEScreenPercentage 0`, `r.ScreenPercentage 100`, `r.SecondaryScreenPercentage.GameViewport 100` and `r.DynamicRes.OperationMode 0` through native session console commands. Read them back; this measures a fixed-resolution diagnostic condition, not the untouched default setup.
2. Warm each representative view, then collect a bounded set of distinct `SystemLibrary.get_frame_count()` samples in a post-tick callback using `PerformanceService.frame_timing()`. Assert PIE is active and camera/settings match before and after. Check timing tuples actually vary; unique frame IDs alone do not clear stale timing values. Report sample count/duration, median/p95 and the usable thread split; flag a mostly-zero or stale thread timer as unavailable rather than interpreting it as negligible cost. Other independently varying frame/GPU timings can still support their narrower observations. Omit the service's default FPS verdict unless that target was approved. Do not call a frame render-thread bound from `frame_timing()` alone: its render-thread time includes waits on the RHI fence/GPU `Present`. Confirm with `stat dumpframe -ms=0.4 -root=RenderThread` (subtract Wait/Stall entries) and a screen-percentage-only change; if render-thread time falls with GPU time, the frame is GPU-bound.
3. Outside timed sampling, execute `DumpTextureStreamingStats` at the relevant views and after bounded camera movement. Read actual log output for pool size, current/target allocations and nonstreaming mips. Trace the camera path against the current road when needed, but label it a loading observation, not Character traversal, hitch analysis or whole-world streaming verification.
4. Restore and read back every CVar and viewport control, stop PIE, verify dirty/package parity, and retain only the concise result in the current report. Leave production unchanged when no in-scope defect is found.

## Bounded road-surface treatment

Use when refining an existing road inside accepted terrain and woodland, not redesigning the route.

1. Inspect controlling references, source asset provenance, saved road mesh/materials and matched road/overview views. Separate surface quality, immediate shoulder integration, local landform and destination composition; an enclosed straight corridor cannot prove a descending woodland exit toward fields. Select suitable surface/stone/litter ingredients through [close-surface asset fit](asset-selection.md#close-surface-asset-fit) before shader authoring or mass placement. Identify which cues need shallow geometry and which can remain shading. Declare the treated section and protected plan, overall grade, width, vegetation and paint; obtain a bounded scope decision for conflicting terrain/ground-floor requirements rather than promising the full reference from a surface-only pass. Derive extent from actual scene/reference views, not a standard sample length.
2. After an ambiguous native material-connection result, inspect the exported wire and compiler diagnostics before retrying: a false boolean can accompany an applied connection. Read Custom input arrays through `get_editor_property('inputs')`, not direct `.inputs`, and reconcile already created nodes. For instanced embedded stones, bound exposure by each scaled mesh height so small variants cannot sit entirely above support; check saved transforms and rendering, and explicitly disclose world-placed dressing that does not follow subsequent spline edits.

   Preserve useful ground blending and the road's distance/lateral UV convention, but reuse generic world-space noise only where it meets the intended surface quality; do not make it the default replacement for suitable scanned surface maps. Keep separate surface/shoulder instances where their baseline colors differ, and taper the treatment back to those baselines at section ends. Query actual parameter names before setting overrides; a getter for an invented name can return a plausible zero/default instead of reporting the missing parameter. Check native graph connections and compilation before assignment; duplicated master defaults do not inherit instance overrides automatically. When integrating suitable imported maps, reuse existing texture samples and masks before adding another material stack: use fines as the continuous base, localized coarse aggregate as an accent, and reduce the coarse contribution in traveled lanes. Expose only useful tile, surface-response and blend controls on the existing instances. Inspect the vendor graph for packed-channel meaning rather than guessing from a filename; native `ObjectExporterT3D` through an automated, non-prompting `AssetExportTask` can reveal function connections when a material-graph exporter does not support functions. Verify sampling projection and normal space together: world-XY samples cannot be fed unchanged into a road's tangent-space normal path, and changing the material's normal-space flag alone is not a coordinate transform. Confirm the shader's actual texture dependencies after compilation. Treat grain, partly embedded stones and organic edges as separate visual jobs: darkening the road or increasing procedural flecks alone does not supply stone silhouette/contact. Keep larger stone placement independent of the forest's accepted population and source assets.

   For repeated shallow stones, reuse suitable existing meshes through a task-owned actor with native `InstancedStaticMeshComponent`s, not one actor per pebble. Discover `ActorToolset.AddComponent`, add each component through `vibeue.exec_tool('EditorToolset.ActorToolset', 'AddComponent', {'owner': {'refPath': actor.get_path_name()}, 'componentType': {'refPath': '/Script/Engine.InstancedStaticMeshComponent'}, 'name': component_name})`, then resolve it from the actor and call `add_instances(transforms, True, True, False)` for world-space placement without navigation updates. Sample actual spline-component collision for the traveled surface and Landscape collision outside it; interpolated centerline height alone misses shoulder elevation. Set collision explicitly for the intended role, verify transforms/counts and inspect contact from low views. Bound-based sinking is a starting placement estimate, not proof that the actual stone geometry meets the soil. World-space dressing remains fixed when a spline moves: disclose that authoring ceiling and re-ground/reposition it after route edits rather than claiming automatic adaptation. Save/reopen and verify PIE before claiming persistent instancing correctness.
3. Match shoulders to the existing soil instead of repainting terrain to hide a band. Export the accepted composited paint, map road vertices into its grid using the actual Landscape origin/spacing, and reproduce the material's normalized base and overlay blend order. Encode the resulting soil RGB with `GeometryScript_List.convert_array_to_color_list` and `GeometryScript_VertexColors.set_mesh_per_vertex_colors`. Feed VertexColor into the road shader, retain the shared world-space modulation, and feather an irregular traveled edge into that soil. This is a sampled blend, not an RVT or exact per-pixel match; judge both shoulders from actual views.
4. For physical wheel wear, interpolate the existing cross-section, add only needed lateral samples in the owned section, and taper shallow offsets to zero at its joins. Stitch unequal row widths monotonically without duplicating the road surface; preserve the original rows elsewhere. Check `GeometryScript_MeshQueries.get_triangle_face_normal` against known-good native geometry rather than assuming a handwritten cross-product sign matches Unreal's winding. Separate inherited out-of-scope defects from introduced ones; do not weaken the owned-section check to make it pass.
5. Verify every triangle's UV/color data and the intended connected-component count before saving. Save/reload the task mesh, material, instances and map, then trace the route across wheel lanes, center and shoulders with both simple and complex collision through transition ends. Hash positions plus topology/UV/colors when those attributes drive appearance; vertex positions alone cannot prove the saved shoulder shading survived. Compare protected actor/foliage state and terrain/paint through the same baseline read paths.
6. Capture matched near, useful medium, detail, overhead and approved panorama only as needed for the claims. Tell image inspection which conspicuous marks are branch shadows and which pale areas are inherited stone, without instructing it to approve the result. If shadows hide wear, inspect a less occluded/native view before changing lighting or deepening ruts. Report subtle wear, shader-only stone relief and remaining edge regularity honestly; technical checks do not decide the reusable look. Inspect actual LOD/cull settings and loading before adding distance infrastructure, then measure meaningful scene cost under recorded conditions.

## Bounded mesh-shape refinement

Use when an existing volumetric surface works procedurally but needs one small silhouette improvement, not a replacement generator or material redesign.

1. Preserve the working foundation and record the task meshes' source-model vertices, topology, material slots, placement records and protected scene baseline. Inspect matched low-angle and overview views; decide whether the defect is shoulder shape, underside exposure or shading before choosing a mechanism. For patchy surfaces, separately record footprint and exposed-ground gaps, which patches join, crown-to-ground height, shoulder cross-section and contour sampling. Treat accepted distribution as a preservation target, not permission to increase coverage when adding volume. Keep collision-clearance margins in world units independent of tessellation spacing so finer geometry cannot silently move roads or exclusion boundaries.
2. For an already normalized snow mesh with `min(local Z)=0`, `max(local Z)=1` and all vertices within that range, a tested minimal shoulder easing is `(x,y,z) -> (x,y,z*z)`. Assert those bounds first; preserve XY, topology and local peak height. Treat this as a bounded candidate, not a universal snow recipe: it can soften the broad shoulder while leaving an angular underside wedge. Keep vendor originals and population settings unchanged.
3. Copy `SOURCE_MODEL` into a transient DynamicMesh, obtain a dense vector list with `GeometryScript_MeshQueries.get_all_vertex_positions`, and write the changed list through `GeometryScript_MeshEdits.set_all_mesh_vertex_positions`. Recompute normals, then use `GeometryScript_AssetUtils.copy_mesh_to_static_mesh` with `replace_materials=False`. Discover target-version signatures and validate outcomes. Derive float32 expectations from the authored coordinates before saved readback; follow the native-precision recipe below.
4. Save only the owned meshes. Unload the map before reloading mesh packages, release UObject wrappers between calls, then load the saved map and compare exact expected positions and preserved placement records. Perform one explicit Generate when that workflow is part of acceptance and compare the complete output, not just its count. Recompute transformed surface/collision samples from the new mesh; old exposed-triangle totals no longer describe the tapered geometry. Distinguish unchanged local peak height from observed terrain exposure, which can decrease when intermediate vertices lower. Exercise representative Character movement across the changed volume.
5. Capture the matched low camera and useful overview, inspect both, and present one labeled comparison. Choose the low view from actual surface/support heights so it stays above the edited volume and exposes an unobscured crown, shoulder and ground contact in one frame; a camera inside a large patch cannot judge regional coverage. Disclose exposure differences instead of crediting brightness changes to geometry. Corroborate image descriptions with geometry/material readback: a surface that looks painted can still have physical depth, and a claimed mask defect is not a diagnosis of a clipped mesh. State any remaining side-face artifact and stop for the creative verdict; technical persistence and collision passes do not approve the silhouette.

### Patch-surface shape acceptance

Use these checks for snow, mud, sand or other accumulated patch surfaces; they are acceptance procedure, not a validated mound-generation formula.

1. Before full-region generation, exercise one isolated patch and one joined pair on flat support and a representative slope in the same small evaluation map. Preserve the accepted gaps and large-scale locations; reuse the accepted volume function when only the outline is rejected. Use broad asymmetric bays, offset lobes and independently retreated sides before fine edge variation; tiny radial ripples retain the regular-pad silhouette. Smooth the merged neck itself, because a hard maximum between lobes creates an inward cusp. Label fixed demonstration contours honestly rather than calling them seeded regional randomness or weather simulation.
2. Show the entire footprint with margin in a top-down orthographic capture, then the crown-to-ground silhouette in a true side profile and a low oblique. Set `capture_scene(..., ortho_width=...)` and yaw to fit the patch's long axis inside the actual image aspect; clipping the ends conceals oval regularity. Isolate other trial actors with `set_is_temporarily_hidden_in_editor`, restore them in `finally`, and keep support-panel edges/shadows distinct from snow defects. Inspect convex crown, rolling shoulder, grounded taper and the lower saddle between joined lobes; peak height and finer tessellation cannot establish those cues. When masks produce flat sheets, trial a boundary-distance profile in world units, with boundary Z pinned to support and smoothing that retains the saddle. Test for a flat cap and medial ridge: capping the height function can make shelves, while unrestricted smoothing can erase the saddle. This is an isolated demonstrated mechanism, not a proven regional generator or universal snow formula.
3. Measure footprint separately from mesh storage: projected triangle union estimates horizontal area, not visible snow or art approval. Sum absolute XY triangle areas only after establishing that the surface has no overlapping projected faces; otherwise compute their union to avoid double-counting. Keep the denominator fixed across revisions. Count connected regions across storage-chunk boundaries by shared world coordinates when connectivity matters; chunk count is not patch count. Report largest-region area or fraction as well as total coverage, because a small threshold shift can merge many islands into one dominant remnant. Compare negative space and representative joined/isolated shapes visually, not just total area.
4. Check actual emitted face interiors and boundary regions against the intended support and collision. Retain failures with face coordinates before asserting aggregate success; valid topology and sampled fixture collision do not prove every generated face collides. Keep support tolerance distinct from intended material depth, and do not enlarge either to clear an unexplained miss.
5. Bind the trial to its actual authored geometry: exercise the shared C++ profile through the existing fixture/export seam, update only the preview's vertex positions with `GeometryScript_MeshEdits.set_all_mesh_vertex_positions`, recompute normals, and rebuild collision once after final geometry. Retain explicit numeric expected digests for cold readback and all emitted-face collision/support checks; changed contour inputs invalidate old mesh hashes, area figures and traversal evidence even when the profile function is unchanged. Keep the current report current and mark superseded results historical instead of nesting another full verification ledger.
6. Expand only a useful representative result within the authorized integration scope, then verify actual generator wiring, clipping, chunk seams, regeneration, affected clearance/contact, traversal, persistence and cost. A test-only profile and saved preview are not integration. For large-scale nearest-boundary queries, inspect the installed `UE::Geometry::FSegmentTree3` API and index flattened XY boundary segments instead of scanning every boundary edge per vertex; compare the resulting prototype geometry against the accepted authored input before adoption. Shape and compute normals on the complete supported surface before partitioning so storage edges do not become artificial melt boundaries. Check actual shared edges at stored float32 normal precision rather than comparing coincident disconnected fans or double-precision averaging noise. Record frame timing only after generation/tests/capture queries finish. If the trial reaches a project stop gate, retain diagnostics and recover the accepted baseline rather than promoting the failed method.

### Projected-coverage calibration

Use when the user changes the amount of an already accepted patch surface, not its profile or materials.

1. Freeze the current scene's domain, seed, geometry, population and protected terrain/route/material baselines. Record the requested projected fraction and any measurement tolerance before tuning; disclose an assumed tolerance rather than silently redefining the target. Reuse the existing occupancy threshold/bias when it can achieve the change without moving clearances or altering accepted shaping.
2. If an offline fit saves repeated builds, reproduce the installed engine's field numerics, including float conversion, seed wrapping and terrain/exclusion caps. Validate that model against the actual baseline before using it. Bracket a monotonic threshold and use bounded bisection to select a candidate; account for the observed baseline model discrepancy, but label the estimate as prediction, not generated acceptance. Keep calibration dependencies and one-off fitting scripts task-local rather than adding a runtime framework.
3. Apply the smallest candidate change, build when required, request one explicit Generate, then read settled output in a later call. Do not replay Generate because the first observation still reports generation in progress. Compute actual projected area from emitted geometry over the same denominator; support rejection, snapping and clipping can differ from the modeled field. Report requested and measured percentages separately, with percentage-point error. Stop tuning once the stated tolerance and visual intent are satisfied.
4. Recheck collision/support and road clearance on the changed geometry, shared-edge continuity, connected-region sizes and matched close/overview views. Preserve the accepted profile implementation and unrelated scene records. Coverage growth changes connectivity nonlinearly, so matching the area alone cannot establish natural partial merging or remaining exposed ground.
5. Save the task output and compare repeat Generate, cold reload and post-PIE state with its canonical geometry and protected baselines. Reuse prior width/shelter tests only as labeled historical evidence unless rerun for this revision. Capture current cost when needed without treating separate-process before/after timings as a controlled delta.
6. Finish semantic readback and any authorized verification-only package flush before recording final package hashes; Landscape readers can dirty a package. Refresh a hash only after explaining its path-specific change and proving the intended saved state. Update the existing current report and checker in place, retain a compact labeled comparison, and leave production promotion separate.

## Single-map cook evidence

Use when an asset foundation needs its first real target-platform compatibility check without claiming a packaged game.

1. Reconcile task-owned saves and dirty state, then gracefully close the owned Editor and confirm it exited before the heavy cook. Use the engine/project paths established by environment discovery, an explicit target map, a fresh task-local output directory and retained logs; avoid overlapping Editor, PIE, build and cook workloads.
2. A verified direct commandlet shape is `"<Engine>/Binaries/Win64/UnrealEditor-Cmd.exe" "<Project>.uproject" -run=Cook -TargetPlatform=Windows -Map=/Game/Path/Map -OutputDir="<task-output>" -unattended -nop4 -NoSplash -stdout -UTF8Output -NullRHI -abslog="<task-log>"`. Use the project's required build/relaunch script separately; this command checks cooking, not compilation, rendering or gameplay. Record the real process exit code and complete log before reporting success.
3. Verify completion and the actual error/warning summary. Reconcile cooked, skipped and total packages from the log. Report headless service warnings with their exact category and disposition; do not silently suppress them or infer success solely from exit code.
4. Inspect output metadata as well as loose files. A successful Zen-backed cook can store package payloads in the local Zen store rather than emit loose `.umap`/`.uasset` files. Check `ue.projectstore`, the generated `AssetRegistry.bin` and `Metadata/ReferencedSet.txt`; confirm the requested map and changed asset paths are present, accounting for metadata path casing. Do not rerun a successful cook merely because loose packages are absent. Retain concise results and artifact fingerprints; mark the Zen store and ignored output as local-only.
5. Refresh the saved-scene/protected-package gate after cooking. Report **map plus dependencies cooked** separately from **executable packaged/launched** and **standalone performance measured**. `-NullRHI` verifies no visual behavior, and a PIE observation does not fill either later gate.

## Native-precision mesh persistence

Use when authored Python coordinates and cold StaticMesh source positions differ only through numeric storage.

1. Confirm source precision in the installed engine (`FMeshDescription::GetVertexPositions()` uses `FVector3f` in the verified version). Preserve the original authoring rows and their order; never derive the expected digest from saved readback.
2. Encode the expected XYZ rows with `b''.join(struct.pack('<fff', *row) for row in authoring_rows)` and record SHA256, encoding, vertex range, total vertex count and triangle count in the existing bundled check input. For a local append, restrict the digest to that append while preserving the old geometry separately.
3. Cold-load through `GeometryScript_AssetUtils.copy_mesh_from_static_mesh` with `SOURCE_MODEL`; encode the extracted range identically and require exact digest/count equality. This tests native precision without weakening geometric limits.
4. Exercise rejection with a deliberately wrong digest or changed coordinate, restore the genuine expectation, then run the maintained live call chain. Keep the check independent of ignored recovery files and run collision separately; position persistence does not establish UVs, normals, topology equivalence or appearance.

## Road-authoring conversion checks

Use when replacing baked roads with an editable representation. These are inspection and acceptance checks, not a validated conversion script. For a terrain-first alternative, establish a no-road forest/base/paint baseline, then verify new-road clearance and complete removal against it; latent candidates across the whole tested stand allow restoration without a special original-road infill mask. For native UI acceptance, use actual drag/property/Ctrl-click/Delete/Generate controls with MCP observations only, not hidden rebuild/flush repairs. A fresh disconnected Landscape spline uses default width and no paint layer: configure points and segments separately. Branch creation can auto-rotate its junction; compare the resulting route state after deletion instead of assuming it reverses that rotation, and distinguish cleanup from transaction Undo. Native spline rebuild requests a deferred layer merge: for scripted edits call the task Landscape's `force_layers_full_update()` before one explicit PCG Generate, then verify on a later tick. A second Generate can conceal stale-collision timing and is not proof of a correct single-Generate workflow. If PCG Landscape interpolation differs from collision, prefer an existing filtered complex World Ray Hit projection and check actual generated roots; do not raise tolerances to hide floating details. Treat that bounded restoration separately from general regional growth and automatic new-span dressing. For clearance verification, match the implemented native pointified polyline before comparing a denser analytic curve: sampling representations can disagree near the margin without runtime exclusion failing. Do not initialize transient PCGLandscapeSplineData by assigning `.spline`; its reparameterization table remains empty and distance queries can assert. Use engine-created data or native text exports for observations. For generated root offsets, derive expectations independently of measured height; a single-valued offset across every possible matching authored source is valid, while nearest offset-set membership is not. For new-span dressing, first try a native tagged-Landscape GetSpline → horizontal SplineSampler → variation TransformPoints → Projection → embed TransformPoints → StaticMeshSpawner branch, with a filtered complex WorldRayHit query supplying the projection target. Sample current native segments rather than storing candidates for every span; explicitly test a road created after the graph, branches, split and removal. Configure a new spawner's existing weighted selector through `entry.get_editor_property('descriptor')`, nested `set_editor_property` calls and writing the `mesh_entries` array back; do not assign the read-only selector class or assume descriptor has a direct Python attribute. Inspect required and terminal edges before Generate: native PCG edge `input_pin` is the source and `output_pin` the destination. Confirm that convention from current endpoint readback rather than guessing from the names. For by-attribute mesh-spawner collision, access `template_descriptor` through editor properties, then read/write its nested `body_instance`; profile/enabled are not direct descriptor fields. Detaching a generated component's graph can clear managed output, so do not save the emptied map during reload; retain verified task recovery and check actual instances after reassignment. Set detail collision explicitly and check generated instances, not just graph settings. Native preview spline meshes may be hidden-in-game and non-colliding while `is_editor_only` reads false; verify the actual properties rather than assuming the flag from the mesh name.

1. Inventory all road surfaces through their construction sources and saved scene: main routes, village lanes, disconnected crossing approaches and junctions. Separate bridge decks from their road approaches so an all-road conversion does not silently omit lanes or deform a protected bridge. Record routes, widths, grades, gaps, material slots and terrain-contact baselines; retain a verified recovery copy of the current saved state, including uncommitted work, before replacing the representation.
2. Inspect material and mesh dependencies before reusing them on deformable sections: distance/lateral UV units, world-position section masks, vertex-color soil blends, cross-section relief and collision mode. Preserve or deliberately regenerate these attributes; repeated tile UVs can reset wear, world masks do not move with edited roads, and a generic section does not retain location-specific shoulder colors. Discover the exact native interface and inspect its engine implementation before choosing mesh axes, width scaling or tangent conventions; an available API is not proof that the conversion works.
   For a bounded replacement with fixed neighbors, check the saved join before constructing the interior. Copy each adjacent source mesh into a transient DynamicMesh with `GeometryScript_AssetUtils.copy_mesh_from_static_mesh` and `GeometryScriptMeshReadLOD` set to `SOURCE_MODEL`; extract vertex positions with `GeometryScript_MeshQueries.get_all_vertex_positions` and select the actual minimum/maximum forward-coordinate row. Compare its lateral/height cross-section with the replacement profile using the generated component's start/end scales and spline frame. A shared control-point height can coexist with substantial baked source offsets. Corroborate with simple/complex traces inside actual triangle coverage; persist individual misses instead of aborting the whole diagnostic at an assumed edge ray. For pitched, relieved adapters, interpolate source-triangle Z before deformation when choosing ray XY: projecting a z=0 frame point can land beyond the physical endpoint. Retain the rejected frame-ray results and trace the adjacent protected section to distinguish a checker-domain miss from a true hole. If the original adjacent cross-sections match each other but not the replacement, preserve that evidence and return the exact boundary decision before modifying protected points or neighbors. A proposed transition piece is not a verified seamless join. After constructing all native connections, reapply authorized fixed endpoint rotations with `LandscapeService.modify_spline_point(..., rotation=required_rotation, auto_calc_rotation=False)`, then call target-only `rebuild_splines` and measure on a later Editor tick: `ConnectSplinePoints` auto-rotates both ends. Compare generated world-space boundary vertices, not just equal source XYZ or control-point positions. Before authoring a fixed adapter, measure the baseline join as a continuous physical cross-section as well: accepted neighbors can have denser endpoint topology, so vertex-count equality is not a continuity test. Keep any inherited gap separately identified; do not relax the new join gate to hide it. Preserve the profile's distance/lateral UV scale and orientation on compatibility meshes; inherited world-fixed UVs can create broad crosswise bands while geometry passes.
3. Choose the authorized branch before terrain work. For representation-only conversion, disable point/segment terrain raise/lower and paint, and preserve heights/weights through matching read paths. For editable grading, use a dedicated native Spline Edit Layer and route-driven paint; verify moved influence clears from the abandoned footprint. Existing base-baked cuts and separate support banks do not disappear merely because a spline layer is added. Preserve crossings/end anchors and inspect full-width joins/bends in both branches; conversion-only safeguards are not permanent grading policy. On a production-scene copy, check fixed snow/litter support separately: unchanged transforms can float or become buried after grading. Compare actual baseline and edited collision at the same bottom-center positions; use those as representative contact diagnostics, not full mesh-contact proof. Measure terrain-to-retained-ribbon steps across the full join even if a Character walks across. Report a protected dressing or join conflict before expanding into re-grounding, adapter fitting or bank replacement.
4. Exercise the intended authoring workflow: move a representative control point laterally and vertically, adjust its curve or width, and confirm the rendered surface and collision update. When testing ordinary Editor usability after scripted correctness, create a fresh road and branch through native controls, drag/widen it, click the real Generate button once, then remove it and exercise Undo/Redo. Observe settled terrain, paint, clearance, grounding and abandoned-footprint recovery through structured readback, without calling spline rebuild, `force_layers_full_update()` or another Generate on the user's behalf. Label any required extra step as part of the actual workflow rather than hiding it in the checker. Observe generated records before Generate too, since automatic regeneration would violate an explicit-Generate workflow. If input delivery blocks the test, retain the last verified mode/map/dirty state and request the smallest manual activation; do not substitute scripted edits and credit a UI pass. Restore the intended route, save/reload task-owned packages when changes are retained, then verify control-point/segment references, route joins, simple and complex traces, and protected scene state. Inspect near, crossing and overhead views. Deliver concise native-control instructions and distinguish surface-quality, scripted correctness and native-UI acceptance.

## Cloned Landscape promotion

Use when an approved evaluation Landscape becomes production-owned without changing its terrain or appearance.

1. Freeze protected and task-owned package hashes separately; verify recovery of the current saved map, including accepted uncommitted work. Export height/paint through the same read path and snapshot actual generated instances before rebinding. Enumerate production-owned mesh, material, graph and LayerInfo dependencies before copying anything.
2. Inspect both top-level bindings and internal saved references. Audit the native level text export and `AssetRegistry.get_dependencies` with hard/soft package references. Check internal Landscape MIC parents, edit-layer/mobile/collision LayerInfo references and StaticMesh default materials; working component overrides do not establish dependency closure. Treat older exports as historical once a repair is saved.
3. Rebind internal material-instance parents with `MaterialEditingLibrary.set_material_instance_parent` and copied mesh defaults with `StaticMesh.set_material`; read back both. Replace paint LayerInfo through the engine's native target-layer replacement workflow, not only the `target_layers` map. In the verified service, discover `LandscapeService.replace_layer_info(label, from_info, to_info)` before use. Require same layer name/blend and reject merges; preserve source Evaluation assets rather than consolidating or deleting them. Test a necessary service extension with the [Landscape fixture recipe](../../gd-tdd/references/landscape-fixtures.md) before applying it to production.
4. Return to Editor ticks, export height/paint again and compare decoded arrays exactly. Confirm actual PCG records remain unchanged before explicit Generate. Save only owned packages, release export/World references, reload in a separate call and rerun the dependency audit; in-memory binding readback is not saved closure.
5. Explicitly Generate when required, then read actual instances in a later call. Compare against the approved rehearsal/preservation baseline, not a newly reset expectation. Save/reload the generated result, run the maintained aggregate checker and representative traversal, and inspect appearance without reopening final-art scope. Retain offset boundary-query limitations separately from physical crossing results.

When replacing only part of a legacy road, retire old probes by source section/station identity. For stored left/center/right triplets, validate their grouping and classify the whole cross-section by its center station: lateral samples on a bend can cross endpoint Y before the center does. Keep adjacent stations and transfer only retired coverage to the replacement full-width checker. Put boundary, malformed-group and exact retired-set guards in the maintained offline entry point as well as exercising the live call chain.

## Fixed-boundary Landscape support fitting

Use only for authorized fixed transition pieces excluded from native spline grading, after their generated endpoint frames and source cross-sections match protected neighbors. First trace the full fixed endpoint edge against every supporting bank, not just Landscape: if a protected bank is above the fixed edge, no continuous adapter can clear it while preserving both. Obtain a bounded bank/join decision instead of repeatedly lifting interiors. Run face-interior checks early; regular stations can miss terrain saddles between them. This is an offline compatibility fit, not a replacement for editable spline-layer grading.

1. Reuse native point setters to correct frames first, rebuild only the affected Landscape, then return to Editor ticks before measuring. Preserve current package payloads and hashes, including uncommitted work. Record the intended base layer, its authored height array, the spline-layer state and protected route settings; do not derive a base-layer replacement from a composited height export, which would bake procedural grading into the sculpt.
2. Sample face interiors by deforming each source triangle vertex into world space before barycentric interpolation; nonlinear spline deformation does not commute with averaging source vertices. Corroborate the actual collision geometry and retain per-piece/protected-route checks separately from joined-road union coverage, since the latter can conceal missing protected collision. Record actual road/support collision heights at those XY points and at terrain-grid vertices under the adapters. Keep missing support explicit; omit `None` values from fitting arithmetic, but do not count omission as passing support. Fit only where the expected colliding terrain exists.
3. Confirm the heightfield's triangle interpolation against measured collision before solving. With local fractions `u,v`, the verified diagonal uses weights `(1-u,u-v,v)` on `(i,j),(i+1,j),(i+1,j+1)` when `u>=v`, otherwise `(1-v,u,v-u)` on `(i,j),(i+1,j+1),(i,j+1)`. Do not substitute bilinear interpolation: its saddle error can exceed a narrow road-contact allowance. Treat exported PNG heights as quantized diagnostics, not more precise truth than measured collision.
4. Prefer the smallest bounded native-grid delta. If an installed solver is available, a task-local `scipy.optimize.linprog` fit can minimize total absolute cell movement: let `g` be measured road-minus-support clearance and `A` the verified triangle weights; constrain `lower <= g - A*d <= upper`. Use auxiliary variables for `abs(d)`, explicit displacement bounds derived from measured support geometry and the authorized footprint, and a safety margin inside the existing acceptance interval for native height quantization. Diagnose infeasibility from an arbitrary solver bound as a model limitation, not proof that the authorized terrain solution is impossible; sample the full ribbon across tile collars, not just its center. Restrict variables to adapter-support cells; assert a finite solution, allowed cell footprint, displacement bound and predicted clearances before importing. If infeasible, first distinguish approved acceptance bounds from self-imposed optimizer margins and overbroad preservation windows; failure of an unnecessarily tight model is not proof that the authorized fix is impossible. Investigate geometry or the boundary decision without relaxing actual acceptance. Do not add a runtime dependency or general fitting framework.
5. Before fitting across two Landscapes, inspect the full-width crossing and the native grading influence on both tiles. Splitting only at the centerline's tile crossing clips opposite halves of a pitched/wide ribbon; zero base response can mean the specialized spline layer completely owns those vertices. Extend the same native grading curve across the seam on each tile when authorized, without adding a second rendered road. Exclude native `SplineEditorMesh` previews from actual-road acceptance and verify their editor-only/collision state. Do not force a base-height solver to repair a procedural-layer discontinuity it cannot affect. Verify actual Landscape GUIDs: independent logical Landscapes do not share grading automatically, and mirrored native grade inputs require explicit synchronized authoring. On nonaligned piecewise-linear seam grids, include both sides' boundary breakpoints and influenced interval endpoints; include the actual outer road edges, since interior crossing probes can miss the worst breakpoint. Distinguish passing near-seam road contact from terrain-edge continuity: native grade continuation can fix the former while the latter still exceeds the existing gate. Do not infer seam acceptance from a good screenshot or the disappearance of a large cliff. Separate the visible ribbon width from its terrain grading envelope when edge cells blend into falloff; a padded native grade-only envelope can improve road contact without widening the road, but its entire outer transition still needs the same seam check. Derive that transition from exported native falloff strip edges, not only a centerline projection, and distinguish height quantization from actual mismatched curve inputs.
6. Apply the deltas to the preserved authored **base** array with `LandscapeService.set_height_in_region`, leaving the dedicated spline layer separate. Rebuild the target, allow a later tick, and rerun the unchanged checker over the complete affected route, including interiors and joined-piece coverage. Predictions are not acceptance: quantization and procedural layer blending can change the measured result. Calibrate positive and negative base responses near the proposed displacement magnitude; a clipped one-sided coefficient is only an estimate, not proof of signed or large-displacement behavior. Cross-check narrow edge-region height reads against the identical slice of a full-grid read before using them as a solver oracle: a native one-row boundary query can return plausible but incorrect constant values. Preserve conflicting raw results and use the verified full-grid path rather than diagnosing a terrain change from that query alone. Keep safety margins distinct from actual acceptance limits, and do not declare approved geometry infeasible solely because a tighter-margin model failed. Preserve failed probes and the project's retry boundary.
7. Save only authorized packages, release UObject references, reload separately and compare unique sample-key/value mappings; enumeration order is not geometry. Require the original contact bounds, generated boundary-vertex agreement, unchanged protected settings/source meshes, package-scope parity and actual PCG-output parity before any explicit Generate. Check representative entry/exit appearance and paired road-versus-Landscape SceneCapture depth at the effective automatic LOD. Record camera, epsilon and interior-pixel count; two passing cameras do not certify the whole corridor, coarse-tile boundary, dressing, snow or traversal.

## Regional paint coverage

1. Before recommending larger areas, compare the full saved panorama, regional overhead and ground views with the approved composition, then inspect masks and accepted roads, fields and settlement reservations. Separate local route continuity from regional extent: a connected patch or passing corridor samples can still leave most reference-led woodland absent. Do not use old proxy-mass sizes as the forest boundary; judge foreground, flanks and broader land-use transitions in the controlling image. Distinguish canopy/shadow darkness from soil color so missing trees do not become an excessively dark blanket.
2. Sample the existing mask along the actual route and at meaningful shoulder offsets; check field interiors and the villageward/eastern boundary separately. Report sample counts, offsets and read path explicitly. A narrow live grid is a local continuity check, not proof of complete route coverage; use the composited mask for wider footprint/connectivity checks and retain protected-layer hashes separately.
3. Correct the approved deficient footprint as a regional land-use pattern, not a uniform dark blanket: connect woodland, retain the agricultural/settlement openings, and preserve lighter mixed-foothill transitions into mountain rock. For a ground-only lighter transition, first reuse existing Hill/Rock colors and independent paint overlays. Derive the approved transition's full width and continuity from forest-to-mountain relationships; local Hill masks or proxy centers can underrepresent a broad foothill ecotone. A distance-guided feather from the retained mountain mask can cover the interface without new geometry or shader layers. Preserve deep road woodland and local stone cues; check both sparse transition samples and deeper woods separately rather than requiring dense-wood weights inside an approved sparse zone. Feather the boundary rather than painting a straight cleared stripe. Keep named geographic regions within their controlling source boundaries; a visual transition around more of a range does not rename it. Reuse ground detail and preserve localized stone/moisture priority. Inspect contributing layers before treating pale roadside ground as a clearing: rock can remain beneath trees. Woodland-floor coverage cannot prove tree enclosure. Preserve unaffected field sizes, regional coverage and geometry.
4. After import, compare the exported composite with the source and every protected layer. If the first export differs, let Editor ticks advance and export again in a separate call before repainting; an immediate readback can precede the updated composite. If it still differs, investigate the source, layer registration and blend/read path rather than replaying the import blindly. Save/reload and rerun both preservation and representative continuity checks before refreshing images.
5. Preserve an immediately-pre-correction view for a coverage-only comparison; refresh current panoramas, ground sheets and semantic reports from the persisted result. Label any retained timing evidence as prior-state when its material/layer state has changed, rather than presenting an earlier measurement as current performance.

## Native comparison when a capture looks wrong

Before altering terrain or lighting, compare the same pose/FOV through the native viewport:

1. Snapshot the current free-viewport pose, FOV, view mode, exposure, realtime/game-view flags, and background-throttling state. Use a fresh segment baseline rather than a cross-turn pose that may have changed.
2. Discover the live signatures. Disable session background throttling with `PerformanceService.set_background_throttling(False)`, enable `ViewportService.set_realtime(True)`, and set the native pose through `UnrealEditorSubsystem.set_level_viewport_camera_info` without moving the saved camera actor. For shader warm-up, use a bounded `unreal.register_slate_post_tick_callback`: count ticks and elapsed `time.monotonic()` time, unregister when both a short settling interval and enough viewport ticks have passed (5 seconds and 60 ticks are a verified starting point, not a universal readiness guarantee). Return immediately; in a separate call confirm the callback ended and inspect the recapture. Use `finally` to unregister an unfinished callback and restore the snapshot on failure. Tune native viewport exposure independently: `ViewportService.set_exposure` and `capture_scene` manual exposure inputs are not interchangeable, even in sign.
3. Request `unreal.AutomationLibrary.take_high_res_screenshot(width, height, filename, camera=saved_camera, delay=1)` when comparing a saved camera. Retain the returned task, check `task.is_task_done()` from a later call, then locate and inspect the actual PNG. Task completion alone is not image correctness.
4. Confirm output dimensions and framing. Keep a labeled matched crop beside the offscreen capture; a cleaner native image does not establish that a shared artifact is fixed. For causal probes and pixel-delta interpretation, use [rendering diagnostics](../../gd-diagnosing-bugs/references/rendering-diagnostics.md).
5. Restore the segment's original viewport/throttling state and verify dirty lists. If an unexpected pose or dirty-state change appears, reconcile ownership before restoring over it; the saved panorama actor and free viewport are separate state.

## Capture and contact pitfalls

- Persistent SceneCapture view state changes exposure; a warmed capture can export all-black frames. Check actual RGB extrema and never credit black output as clean.
- A minimized Editor stops drawing, so screenshots silently write nothing. Restore unfocused with Win32 `ShowWindow(h, 4)` before capturing and re-minimize with `ShowWindow(h, 7)`.
- The viewport camera can keep drifting from a stuck navigation input; re-apply the camera each Slate tick until the shot is written.
- A narrow baked height spike can look like a berm or snowbank. Compare composite vs base-only heights (Road layer temporarily off), audit the full grid, and repair only proven outlier cells; slope scans alone misclassify mountains.
- Native spline sections compensate endpoint widths from segment geometry; equal local mesh Y isn't equal world width at a join. Check triangle interiors and full-width boundaries after reload: vertex and centerline checks miss hovering faces.
- Road fits must constrain against every existing road footprint under the tile and against the highest actual support (bank or Landscape), sampling triangle interiors and near-end edges; distributed probes miss endpoint tapers.
- Preserving placed-actor transforms across terrain grading doesn't preserve contact; compare bottom-centre support before/after and treat floating or buried results as failures.
- Volumetric-cloud flicker: compare matched frozen-wind PIE views at the same sun direction before tuning; ray length and sample count trade grain against cost. Copy the engine's cloud recipe (one large breakup noise, faint fine detail, soft edges) before adding detail: dense hard-edged cloud reads as cotton balls and sparkles.
