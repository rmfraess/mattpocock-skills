# Maintainable Unreal road authoring

Use for a road-authoring architecture review; recommendations are not migration authorization.

- Read target-version Epic Landscape Splines, Edit Layers and Technical Guide before selecting a road plugin or framework. UE5.8 uses a specialized Spline Edit Layer; do not apply UE4.27 instructions about Reserve for Splines or retroactive layer enablement without version verification.
- Prefer a native route as the authoritative input for grade, width, surface, clearance and route-relative dressing. Separate lightweight native editing from explicit expensive PCG population refresh.
- Inspect source mesh residual heights, fixed world-space shader masks, bank mesh ownership and dressing placement. A spline-backed baked section is editable but not necessarily reusable, extensible or terrain-conforming.
- Measure Landscape XY spacing and Z precision before promising spline grading. Deformation changes height samples, not topology; more spline raster samples or Nanite rendering do not supply missing source terrain resolution. Calculate whole-extent density cost before recommending global upsampling.
- Prefer base sculpt/paint separate from procedural spline deformation. A dedicated spline layer can remove its old contribution when the route changes; it cannot remove old road cuts baked into the base. Include base-footprint reconstruction in a migration where needed.
- Treat terrain resampling as a content migration: installed UE5.8 source replaces the Landscape and resamples height/weight data, clones splines and remaps foliage. Verify recovery, references, paint and ground-selection code before production adoption.
- Before adding a detailed core alongside scenic Landscape, trace every terrain consumer: root height, neighboring slope samples, paint-based exclusion and dressing support. A last-encountered tagged Landscape makes output depend on actor order; choosing the highest surface can ignore a lower detailed replacement. Define overlap precedence, outside-tile fallback and disabled/hole behavior explicitly, and apply the same surface-selection contract to height, slope and paint. Keep the dressing's route owner separate from its ground owner. Require a regression with a lower fine tile over coarse terrain, a coarse-only point, reversed actor order and disabled coverage before trusting regeneration. Own collision, visibility and seams explicitly; a narrow terrain ribbon can recreate the same boundary-maintenance problem.
- Prove move/raise/width/tangent, extend/shorten, split/remove and undo before accepting architecture. Require abandoned terrain influence and generated dressing cleanup, saved reload, current collision/representative traversal and both-direction visible joins. A beautiful static patch is not authoring acceptance.
- Check collision immediately after Undo, not only point values/heightfield exports. For reproduced stale triangle collision, inspect the target engine's native rebuild path before designing custom physics recovery; `Landscape.FixSplines` is a verified explicit recovery in the tested UE5.8.3 configuration, not a general automatic Undo guarantee. Check resident-world/dirty scope before using it because it visits all loaded non-game Worlds. Compare the settled terrain on a later tick, since layer merging is deferred. Distinguish native full rebuilding from `update_mesh()` or equal-value start/end setters, which did not establish recovery in that configuration. For deletion, inspect native `DeleteSplinePoints` teardown and verify the removed footprint as well as active arrays/generated components, because removing references alone can leave orphan mesh/collision and ObjectIterator can retain detached objects.
- Distinguish native UI operations from callable plugin APIs. LandscapeEditor's split helper is private; a service implementation must define its input/metadata contract and test curve continuity. The UE5.8.3 routine copies selected settings and omits the new far-end socket name, so do not promise socket-aware shape preservation by copying it blindly. Test delete-all Redo terrain invalidation as well as Undo and active-array counts. Public virtual methods on MinimalAPI classes without explicit exports require a real cross-module build check, not a declaration-only capability claim.
- Keep RVT/POM as appearance tools, not fixes for geometric support or collision. Do not add experimental PCG Editor Mode when existing native spline/PCG authoring suffices.
