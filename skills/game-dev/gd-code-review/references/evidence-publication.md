# Review and publish game evidence

Use when asked to review uncommitted evidence, keep it useful, and commit/push it. Review the supplied implementation scope rather than silently reviewing all history. This is an offline publication workflow, not permission to resume Editor work.

## 1. Freeze the publication boundary

Run `git status --porcelain=v1 -z --untracked-files=all`, `git branch --show-current`, `git rev-parse HEAD`, and `git diff --cached --name-only`. Parse the NUL-delimited inventory so spaces in paths and untracked directory contents are accounted for. Record each task-owned path, size and Git blob ID, including requested lesson documents. Read complete new text/JSON, tracked diffs and relevant saved-state reports before editing. Preserve pre-existing staging and unrelated work.

For an authorized push, fetch the target remote, then run `git rev-list --left-right --count <remote>/<branch>...HEAD` and `git log <remote>/<branch>..HEAD --oneline`. A local review-and-commit request does not require remote access or authorize a push. Inspect the outgoing commit/file inventory: a branch push publishes earlier ahead commits too, not only the new evidence commit. Resolve unrelated outgoing work or divergence before publishing; use an ordinary fast-forward push, not a force push.

For linked repositories, freeze each repository's remote, destination branch, local HEAD and exact outgoing SHA list in a local record, and verify the host's `git rev-parse HEAD:<submodule-path>` equals the intended child commit. Present additional publication scope together, including parked work already present in the ahead range. After approval, fetch both repositories again and compare the exact outgoing SHA lists, not just their counts. Finish inventory, worktree/staging, whitespace and applicable LFS checks for every repository before starting any push; parallel reads are useful, but a dependent push must wait for the complete preflight result.

## 2. Verify that artifacts earn their place

Match each artifact to a useful claim: accepted appearance, persistence, a maintained authoring/check path or an unresolved limitation. Distill failed probes into an actionable mechanism or limitation rather than retaining their raw payloads as evidence. Retain distinct comparisons, not every raw capture or log. Prefer a final saved/reloaded comparison plus one diagnostic that explains the chosen repair; archive an intermediate comparison when it no longer adds a distinct claim. Trace its Markdown and JSON references before pruning, because a removed image can remain named by a historical result field. Preserve original image bytes unless an actual defect requires correction; record a later creative verdict in the current report instead of re-encoding an otherwise valid accepted sheet merely to change its pre-verdict label.

For a complete pending-artifact audit:

1. Classify every inventory entry as a scene dependency, runnable author/check input, current acceptance evidence, governing direction/lesson, or superseded trial. Trace file reads, Markdown links and saved actor/material references before removing anything; a generic placeholder mesh still earns its place when the saved map uses it.
2. Keep one current result report, required baseline/snapshot, verification result and views supporting distinct claims. Trace callers before retiring one-off authoring helpers; preserve them only when they supply a maintained rebuild/recovery path, not merely a record of construction. Keep final editable sources and useful checks. Traverse JSON fields to identify duplicated expectations, ledgers and repeated success rows; keep expectations once and have results report actual observations/checksums. Update affected emitters and exercise them so subsequent checks retain the compact shape. Preserve current controls and provenance from retired ledgers in the existing report/direction. Replace invalid performance samples with a concise limitation rather than publishing misleading statistics. Remove obsolete captures/progress diaries when current evidence supersedes them; pixel differences alone do not establish useful differences.
3. Prepare and exercise replacement evidence/check inputs before removing their predecessors. Migrate callers, compare old and new expectations, and run the retained entry point with the retired inputs unavailable; only then prune the explicit superseded paths. Separate preparation, verification and deletion into bounded steps, because a single rewrite-and-delete batch can leave every retained validator broken if execution is interrupted. Before authorized pruning, preserve a recovery copy when needed in an already-ignored local location. Record relative source/archive paths, sizes and SHA-256 values and verify the copies. Do not substitute broad directory cleanup or opaque asset deletion for an evidence audit.
4. Preserve the original inventory, then write a separate final reviewed manifest after cleanup and review aggregation. Finish all authorized native diagnostic reads and any necessary owned-package flush before binding evidence hashes: Landscape height/weight queries can dirty or reserialize a map without changing its accepted geometry. Reconcile actual geometry, placements, terrain and paint against the authentic baseline before refreshing a package hash; never replace expectations merely to silence a mismatch. Freeze Editor writes before staging. Bind staged files to that final version; an expected document edit makes the initial hash stale without invalidating unchanged source/build or asset evidence. Require focused re-review and applicable re-verification for executable or asset changes; inspect documentation-only deltas directly. Recompute the pending inventory and verify original paths equal retained plus removed paths, accounting explicitly for additions. Validate retained links, inputs and images; report retention/removal without publishing another session-specific audit document.

### Folder relocation and generator replay

Use for non-destructive organization of research, references and generated deliverables; keep the publication/deletion boundary from the main workflow.

1. Inventory the complete tree by role, file count and bytes, separating tracked content from local recovery/cache files. Identify current deliverables from selection/review records, not names such as `final`, `rejected` or the newest revision. Hash loose duplicate candidates and compare ZIP member payloads before calling exports disposable; an archive can preserve an earlier document version despite duplicating its images.
2. Build an explicit old→new map. Trace live reads/writes, relative `__file__` paths, conditional `.exists()` branches, Markdown links and database path columns; inspect a database read-only rather than grepping its binary bytes. Change both producer and consumer paths. Distinguish live pointers from original request paths, source-sheet names and frozen fingerprint keys: retain historical locators and document how they resolve after relocation instead of blanket-replacing stored strings.
3. Keep selected outputs, established handoffs and recovery inputs at their existing paths where practical. Compare every moved binary with its pre-move SHA-256, account for every original file, and resolve current links and manifest inputs. Keep navigation-only status corrections outside hash-pinned originals unless a versioned provenance correction is authorized.
4. Copy the retained generators and all declared inputs into a disposable mirror before exercising writers. If an old preservation snapshot belongs to another epoch, leave the original untouched and build a clearly labeled, full-set scratch fixture from the copied current inputs: retain every protected logical entry and verify cardinality/uniqueness after path mapping. This tests current replay preservation, not whether the historical baseline passes today. Invoke the actual scripts through a subprocess or `runpy.run_path(..., run_name='__main__')`; an import is not execution.
5. Exercise both valid replay and rejection of a deliberately changed protected non-image file. Require failure at the intended preservation assertion, then restore the fixture and rerun. Retain complete guard coverage; filtering checks to images would hide document, code or database damage. Compare rebuilt outputs with the frozen copied payloads, allowing only explained differences. Verify ZIP member names and bytes against loose outputs rather than expecting identical container bytes, because archive timestamps can change. Keep the real handoff ZIP and selected files untouched.
6. Reconcile the final Git inventory with the move map, declared text edits and additions; rerun relevant existing checks. Report relocated files and remaining limits briefly: moving bytes does not reclaim storage. Keep scratch fixtures, recovery manifests and replay logs out of the repository unless they are requested deliverables or maintained checks.

### Native Unreal package pruning

For authorized asset deletion, audit the saved map's transitive hard/soft package references with `AssetRegistry.get_dependencies` and check `get_referencers` for references outside the deletion set. Inspect native assembly-part paths too; ordinary material/actor references alone can miss assembled foliage dependencies. Verify recovery copies, then delete the explicit unreachable closure through Editor APIs, with unused referencers before their dependencies.

Reconcile an ambiguous native deletion before retrying; a successful return can remove an in-memory asset or index row while leaving its package file on disk.

1. Read back every exact target through both `EditorAssetLibrary.does_asset_exist(path)` and `AssetRegistry.get_assets_by_package_name(path, True)`, then independently check its native `.uasset`/`.umap` file. Inspect dirty maps/content and protected hashes. Do not infer complete deletion from one of these states alone.
2. If a file remains but its registry entry is absent, use the discovered `AssetRegistry.scan_files_synchronous([absolute_filename], True)` to reconcile that exact file, then repeat the external-referencer gate. Do not rescan or delete a whole directory to conceal the discrepancy.
3. For an authorized unreachable deletion set, load the remaining exact assets into a function-local list and keep that list alive through `get_editor_subsystem(unreal.EditorAssetSubsystem).delete_loaded_assets(loaded)`. This exercised path keeps the deletion inputs available through native object/package cleanup. Verify all target files, registry entries and asset-existence queries are absent afterward; do not credit the boolean alone. Respect the project's retry limit across single and batch variants.
4. If live references still prevent cleanup, use a targeted relaunch only after all dirt is identified as backed-up disposable task work; reconcile ownership/world before resuming only surviving targets. Never delete package bytes directly as a substitute for native cleanup.
5. Verify recovery hashes and every surviving protected package, unchanged accepted geometry/instances, and dependency closure with no removed targets. Inspect the accepted scene and restore session controls. Reuse unchanged build/collision evidence; do not regenerate or save the accepted map merely to prove unrelated asset deletion. Report the recovery location and whether it is local-only.

Decode retained images with the available library, call `verify()`, and inspect dimensions, alpha and original-resolution labels. A labeled review sheet can replace raw captures for coarse appearance claims after checking panel provenance, current state and sufficient detail; keep full-resolution views where regional extent or surface defects need them. Validate alleged duplicates against original decoded pixels. Recompute quantitative claims from available raw sources. For projected mesh coverage, have the maintained live checker sum signed XY triangle areas over every actual saved face, reject nonfinite/degenerate/inverted faces, and divide by the explicitly recorded domain. A stored fraction within tolerance plus a mesh hash only binds an earlier measurement; it does not execute the measurement. Check shading normals across the actual overlay, not only one triangle. Keep production-preservation evidence separate from an Evaluation-only checker: name the frozen package manifest or native dependency audit that establishes it, including missing legacy dependencies rather than claiming universal reference health. Use `hashlib.sha256` for provenance and `ImageChops.difference(a.convert('RGB'), b.convert('RGB')).getbbox()` for decoded RGB equality; file-hash inequality does not refute pixel equality.

Parse retained JSON and resolve Markdown/capture references after pruning. Exclude fenced and inline code when scanning Markdown links, because research regexes can contain link-like bracket/parenthesis sequences; retain real links whose labels contain inline code. URL-decode local link paths with `urllib.parse.unquote` before checking existence, since encoded spaces are valid links rather than missing files. Check heading fragments as well as target-file existence. Redirect retained camera records to their review-sheet panel and distinguish original capture dimensions from panel dimensions; remove camera entries with no retained purpose. Compare source hashes when files exist and mark unavailable originals honestly. Keep saved diagnostics distinct from current runtime correctness; unchanged inputs can reuse applicable prior evidence without a fresh Editor run. Bind that reuse to the exact verified asset payload and checker inputs: compare their recorded hashes/parsed values with the pending files before staging. Preserve the distinction between a locally passing repair and an aggregate checker that still fails elsewhere; publication must not silently promote either to an all-project pass.

## 3. Fix usefulness and portability in place

State accepted scope, unresolved limitation and current next owner action once. Check linked briefs as well as the edited navigation for stale output status, because an earlier research-only brief can still say no generated artifacts exist. Qualify that statement as historical and link the current proposal without rewriting factual research or implying creative approval; preserve fingerprint-pinned originals and update their current navigation instead. Replace stale open/pending status and completed percentage/change requests with the accepted outcome; condense restoration recaps into one final state plus a result table. Label each check's comparison base: a transform-only final revision can preserve counts/assets while the complete pending change adds both relative to Git HEAD. Qualify earlier preservation claims when a later authorized revision deliberately changes the preserved field; reconstruct the earlier comparison explicitly instead of leaving the current report claiming every old transform is still unchanged. Compact homogeneous ID/index arrays inline when their indentation dominates a report, preserving numeric types, exact values, uniqueness and order. Parse before/after and assert equality of checker inputs and measurements; do not weaken hash checks or round floating-point baselines to make compaction pass. Retain sample values, camera/settings, metric definitions and confounds that change future decisions.

For captured material/scene reports, omit transient session-address IDs, editor layout and irrelevant export boilerplate. Preserve dependency paths, parameter values, meaningful labels, layer registrations and graph topology; stable list indices can replace session IDs if every edge/output is remapped. When collapsing an accumulated scene ledger, apply overrides and additions in their recorded order and compare the final parsed placements with the authentic accumulated expectations before discarding old inputs. Keep instanced foliage as ordered rows or explicit unique IDs; empty actor labels are valid and a label-keyed dictionary silently collapses those placements. Reconcile total and per-type/species counts, actor-label uniqueness where labels are required, transforms and source paths. Intern repeated asset paths and retain one transform record per placement rather than another override history. Compare parsed compact records against the authentic original capture before discarding it. When retiring nested revision histories, retain the latest geometry/runtime/build observations once beside the single exact placement snapshot; keep historical overrides and raw journals in verified local recovery rather than another committed ledger. Assert equality of placement rows/order, type assignments, counts, dependency closure and protected-baseline fields against the frozen snapshot before removing old sections. Validate retained metadata against its real type and source: material-slot indices are not material asset paths. Correct such inherited placeholders from native readback rather than carrying them into a compact report. When only report serialization changes, exercise the changed emitter with authentic saved observations and verify semantic equality; call this an offline emitter check, not a new live scene test. Do not invent engine responses to make a verifier appear replayed. Changes to actual engine-check behavior require its appropriate live verification.

Label ignored `Saved/` captures, GPU dumps and sibling-repository references as local-only when they are not included. Absolute paths and hashes can remain truthful provenance, but are not portable attachments. Preserve the recorded identifiers; add availability context rather than rewriting source tokens or importing a large raw dump merely to make every path portable.

Trace each retained verifier through its inputs and assertions before pruning reports. After representation changes, look for stale exact actor totals, hidden-state expectations, collision targets and source paths; a passing offline evidence check does not exercise those live assertions. Retire an obsolete validator only after locating callers and updating report instructions to the maintained successor. Label any retained pre-migration report as historical so its successful old checks are not mistaken for current-scene verification.

When consolidating expectations, distinguish an authoritative preservation baseline from a fresh observation. Do not replace prior expected transforms, counts or digests with current readback merely to make the checker pass; first reconcile the observation against approved deltas and the old baseline, retaining unresolved mismatches as findings. When multiple checks duplicate one placement ledger, compare asset assignments, transforms and counts against the existing authoritative snapshot before removing the duplicate. Delegate preservation checks to the maintained owner of that snapshot, including references, transforms and hidden recovery state, not merely total counts. Keep route-specific geometry/contact expectations in the road checker and forest expectations in the forest checker. Replace stale whole-map actor totals with scoped expectations when native generation adds actors; retain exact totals where they still define the owned result. Exercise the updated live call chain once under exclusive Editor ownership; unchanged packages permit reuse of prior build/appearance evidence, but changed checker logic needs its own execution evidence.

Check the retained verifier's input paths before pruning reports: bundled evidence is not portable if its normal verification still reads ignored local artifacts. Test current-library queries/checks in an isolated directory containing only the retained tools and all declared repository inputs, without original source directories or ignored backups. Run the actual entry point with `runpy.run_path(str(isolated_script), run_name='__main__')`; do not credit an import that never invokes the check. Refresh every declared payload in the isolated copy after final verification/saves, not just the JSON and script, because a stale copied map can fail an otherwise correctly bound portability check. Distinguish normal verification from initial migration replay: replay may require a prior Git blob and a fingerprint-pinned external source artifact; state those additional inputs and their local-only availability explicitly instead of claiming portable replay or committing a raw dump merely to satisfy it. Reuse the one current bundled report/snapshot. For exact immutable numeric baselines, replace a bulky local-only raw input with a recorded whole-grid checksum only after deriving it from the original baseline plus the recorded delta and independently matching actual engine data; preserve count/order/encoding and rerun the full check with the old input path blocked. Keep raw recovery data ignored/local, not in the publication inventory.

Keep reusable mechanisms in the project's lesson document when requested, not a dated narrative. Route future execution through the applicable class-level skill.

### Exact-byte manifests and ZIP companions

Use when a manifest fingerprints loose documents or an archive promises identical companion files.

1. Parse the manifest and archive. Verify declared sizes/hashes, unique exact member names, CRC and each member's payload against its loose file; decode images and check measured dimensions. Preserve the original archive when it already passes.
2. Inspect `git config --show-origin --get core.autocrlf` and `git check-attr text eol filter -- <companion-paths>`. Check actual LF/CRLF bytes for every fingerprinted text companion, including JSON; protecting only Markdown leaves cross-platform failures. A matching working-tree hash does not prove checkout stability.
3. During read-only review, reproduce conversion in a disposable scratch repository carrying the effective attributes and relevant Git settings; stage and export only copied inputs there. For an authorized fix, apply narrowly scoped `-text` attributes following the repository's existing pattern rather than changing global settings or renormalizing unrelated files. For deliberately preserved CRLF text, retain the existing `cr-at-eol` whitespace-check convention. When adding byte-preserving attributes to already tracked files, run `git add --renormalize -- <exact-reviewed-paths>` and compare the staged raw bytes with the authentic baseline: an ordinary `git add` can retain an old normalized blob through its stat cache. Never apply that renormalization repository-wide.
4. After authorized staging, export the real staged paths into separate scratch directories with `git -c core.autocrlf=true checkout-index --prefix=<absolute-directory>/ -- <paths>` and the same command with `core.autocrlf=false`. Include the applicable attributes and compare raw bytes, sizes and SHA-256 values in both exports against the manifest and ZIP; require the manifest itself to survive unchanged. Do not repair authentic hashes to accommodate conversion.
5. Confirm the final staged scope and run `git diff --cached --check`. Reuse unchanged source/image/research verification, rerunning the checkout-sensitive checks after the attribute fix. Keep disposable exports and probe logs outside the repository; report the tested checkout modes, not universal platform coverage.

## 4. Acceptance pass

Run `git diff --check`; confirm all requested files are accounted for, JSON parses, local links resolve, claimed measurements match available sources, and edits did not mutate samples or images unintentionally. Recheck the live tracker status through its read interface when the document claims closure. Attribute creative acceptance to the owner's actual verdict, limited to the reviewed scope.

For new-destination database/artifact writers, test failure behavior as well as successful output: inject a backup/write failure and verify no empty or partial destination blocks a retry; test an existing destination and verify its bytes remain unchanged. Reserve the output exclusively, close handles before cleanup, and remove only the partial file created by that invocation. Apply the same tests to recovery checkpoints: reject symlink/hard-link aliases and exercise failure followed by a real retry. Stage and validate new checkpoint bytes privately, then publish atomically without overwriting the final name. Do not reopen a reserved final pathname for SQLite writes or unlink it on failure: a competing process can replace it before either operation. Test competing final-path creation and cleanup failure without masking the original error. A successful normal write alone does not exercise this preservation contract.

Pin historical replay databases to an immutable Git revision/blob rather than the moving `HEAD` library. Export the current code separately, and exercise the suite in a disposable committed checkout whose `HEAD` already contains the new data; otherwise pre-commit passes can conceal tests that fail immediately after the requested checkpoint.

Keep an unresolved Editor-ownership hold intact. Documentation-only cleanup can proceed without Editor access when no content/reload/save is involved. Compare final `git hash-object <package>` values with the frozen inventory to prove cleanup left packages untouched; comparison with `HEAD:<package>` alone cannot isolate cleanup from pre-existing task changes. This establishes on-disk preservation, not current unsaved Editor state.

## 5. Commit the exact reviewed state

Stage explicit paths with `git add -- <paths>`. Compare `git diff --cached --name-only` with the frozen inventory, run `git diff --cached --check`, and compare `git hash-object <path>` with `git rev-parse :<path>` for the reviewed blobs. Preserve unrelated staging rather than committing it accidentally. Commit without amending existing checkpoints, then verify the commit's path inventory and working-tree status. For a nested plugin submodule, commit and verify its exact task-owned paths first, then stage that commit's gitlink plus the bounded host evidence/lessons in a separate host checkpoint; leave unrelated art and intake unstaged. Serialize Git writes per repository. After an index-lock failure, inspect lock/process ownership, actual HEAD and staging before retrying; never remove another process's lock. A retry after the lock clears must verify the same intended staged inventory, since staging may already have succeeded.

### Required large assets and Git LFS

Inspect `git check-attr filter -- <paths>` and required package sizes before staging. Prune unused payloads, not saved-scene dependencies, to satisfy repository/hosting constraints. When LFS is appropriate and within the authorized repository changes, use `git lfs install --local` and narrowly scoped `.gitattributes` entries for the pending asset directories/map. Stage attributes before those packages; leave unrelated assets and existing history alone rather than running a blanket migration or renormalization.

For filtered files, verify both representations: `git show :<path>` must contain the intended LFS pointer, while its `oid sha256` and `size` must match the real worktree package and the local payload under `git rev-parse --git-path lfs/objects` (`<oid[:2]>/<oid[2:4]>/<oid>`). Use `hashlib.sha256` and actual byte counts; raw package hashes are not Git pointer-blob IDs. Confirm the Editor worktree contains full packages, not pointer stubs. After committing, run `git lfs fsck HEAD` and verify the commit inventory and clean/remaining worktree. Local LFS verification does not prove remote payload upload; keep push authorization separate.

## 6. Publish and read back

Push the authorized branch explicitly with `git push <remote> <branch>`. For an unpublished plugin/submodule dependency, push the authorized child branch first and verify `git ls-remote <child-remote> refs/heads/<child-branch>` equals the frozen child HEAD before pushing the host. If the child push fails or its result is ambiguous, reconcile the remote ref before proceeding; leave the host unpublished until its referenced commit is verified available. Record partial publication honestly if the child succeeds but the host does not.

Verify `git ls-remote <remote> refs/heads/<branch>` equals the frozen local HEAD; a successful push message alone is not the final check. For GitHub, `gh api repos/<owner>/<repo>/git/trees/<sha> --method GET -f recursive=1` supplies published object IDs: check `truncated` and compare each reviewed path with `git rev-parse <sha>:<path>`. Verify a submodule entry as a gitlink commit, not an ordinary blob; read back its child repository separately. If truncated, query exact paths or subtrees instead of assuming complete coverage.

For a critical ordinary Git asset, verify payload bytes as well as the published tree entry: fetch its blob with `gh api repos/<owner>/<repo>/git/blobs/<blob-sha>`, base64-decode `content`, and compare it with the reviewed local bytes. Select blob versus LFS verification from `git check-attr filter -- <path>` and the committed blob, not the filename extension; a project can store similar Unreal packages through different paths.

For LFS publication, distinguish uploaded payloads from published pointer blobs. A GitHub tree readback verifies pointers, not downloadable asset bytes. When verifying a critical opaque artifact end to end, use a fresh absolute cache outside the checkout: `git -c lfs.storage="<fresh-cache>" lfs fetch <remote> <branch> --include="<exact-repository-path>" --exclude=""`. Parse that artifact's committed pointer, then verify `<fresh-cache>/objects/<oid[:2]>/<oid[2:4]>/<oid>` against its `oid sha256`, declared byte size and accepted local payload. Do not run checkout, replace the Editor's packages or reuse the populated local cache for this check; a local cache hit cannot prove remote download. State exactly which artifact was downloaded rather than claiming every uploaded object was independently fetched.

Before staging publication-ready documents, replace transient statements such as uncommitted/not-pushed with a pointer to Git as commit/publication authority; otherwise the new commit immediately publishes stale status. Keep actual SHAs and remote readback in the completion report or local verification record rather than a self-referential commit entry.

Finish by checking clean/remaining worktree and staging state in each repository, zero ahead/behind against each published destination, and the host gitlink's equality with the verified child commit. Report the commit, target branch, cleanup, whether earlier ahead commits were published, and clean/remaining working-tree state. Keep the successful report short; name the exact payloads independently downloaded rather than generalizing their verification to every asset, and disclose missing raw-source access or unresolved technical claims only where material.

## 7. Close an accepted issue when authorized

Treat commit/push authorization and tracker closure as separate actions. If the user asks to close an issue and its scoped acceptance is supported, perform closure rather than requesting the same approval again.

1. Fetch the latest issue body/state and published evidence. Map each acceptance checkbox to its technical evidence or the creative owner's actual verdict; do not claim final quality from coarse-pass approval.
2. Mark only verified acceptance checkboxes, preserving requirements and unrelated text. Re-fetch before the write to detect intervening edits, then read back the exact edited body. On Windows, send the fetched body through JSON API input or write with `newline=''`; default text-file newline translation can turn existing CRLF into CRCRLF. Verify exact content after the write, and reconcile a successful edit before retrying when readback differs.
3. For GitHub, run `gh issue close <number> --repo <owner/repo> --reason completed --comment <concise acceptance/evidence summary>`. Keep remaining separately scoped work distinct from unresolved blockers.
4. Read back `state`, `stateReason`, body and closure comment. Confirm completed closure and report the link; neither a successful push nor a successful close command alone proves the intended tracker result.
